# agent-ledger-mcp 3.0.1

## English

### Summary

`3.0.1` is a patch release that fixes POSIX file permissions when `prepare-host` or `render-deploy` is invoked under a restrictive `umask` (such as `umask 077`). Previously, `DeployFiles.replace` relied solely on `Files.createTempFile` with `FileModes.WORLD_READABLE` (`0644`), which POSIX masks with the caller's `umask` so installed jars and rendered configuration files could be written as `0600` (`rw-------`) and become unreadable by the non-root `agent-ledger-mcp` service user. Because every MCP tool contract, attestation protocol, database schema, and CLI option remains backward-compatible with `3.0.0`, the patch version increases from `3.0.0` to `3.0.1`.

### Breaking changes

There are no breaking changes in this release. Existing `3.0.0` MCP clients, client hooks, database schemas (`V11`), configuration files, and service units continue to work without modification.

### Migration

1. Build the `3.0.1` jars with `./gradlew assemble` (no test database required) or obtain the release jars (`ledger-cli.jar`, `ledger-mcp-server.jar`, `ledger-admin-web.jar`).
2. Back up the currently installed `3.0.0` jars under `/opt/agent-ledger-mcp/` before replacing them so rollback is a single file copy and service restart.
3. Re-run `deploy/install.sh` (Linux) or `deploy\install.cmd` (Windows) with the `3.0.1` jars directory and existing options; no database migration runs because the schema remains at `V11`.
4. Verify both `/healthz` endpoints (`127.0.0.1:8765/healthz` and `127.0.0.1:8865/healthz`) return `UP`.
5. To roll back, restore the backed-up `3.0.0` jars and restart `agent-ledger-mcp` and `agent-ledger-mcp-admin`.

### New

- **POSIX `umask 077` regression coverage (`DeployFilesUmaskTest`)**: Added a dedicated POSIX regression test that spawns a child JVM under `umask 077`, confirms that raw `Files.createTempFile` with `FileModes.WORLD_READABLE` is masked to `rw-------` (`0600`), and verifies that `DeployFiles.replace` produces exact `rw-r--r--` (`0644`) permissions for copied jars and rendered configuration files, alongside a cross-platform temporary-file cleanup test.

### Changed

- **Explicit `0644` mode enforcement in `DeployFiles.replace`**: Applied `FileModes.apply` with `FileModes.WORLD_READABLE` (`rw-r--r--`) on the temporary file immediately before the atomic rename in `prepare-host` and `render-deploy`, ensuring jars under `/opt/agent-ledger-mcp/`, rendered files under `/etc/agent-ledger-mcp/`, and systemd unit files are always readable by the `agent-ledger-mcp` service user regardless of caller `umask`.
- **Version alignment**: Updated Gradle build, MCP server metadata, and client plugin manifests to `3.0.1`.

### Removed

No features, endpoints, CLI commands, MCP tools, or settings were removed in this release.

### Security

- `DeployFiles.replace` continues to pass `FileModes.WORLD_READABLE` at temporary-file creation so files are never created with wider permissions even under permissive `umask` settings, and `FileModes.apply` enforces `LinkOption.NOFOLLOW_LINKS` so symbolic links are refused before permissions are changed.
- Secret directories, attachment keys, and attachment storage retain their strict owner-only permissions and are unaffected by this change.

### Requirements

- Java 25 runtime (`JDK 25`) on the server host and client hook hosts.
- Existing `3.0.0` PostgreSQL database (schema `V11`) and registered JDBC driver; no new dependencies are introduced.

### Known limitations

- The `umask 077` child-process test in `DeployFilesUmaskTest` runs on POSIX file systems (verified on Linux CI); Windows hosts enforce access control through directory ACLs rather than POSIX `umask`.

## 한국어

### 요약

`3.0.1`은 제한적인 `umask`(예: `umask 077`) 환경에서 `prepare-host` 또는 `render-deploy`를 실행할 때 발생하는 POSIX 파일 권한 결함을 수정한 패치 릴리스입니다. 기존에는 `DeployFiles.replace`가 `Files.createTempFile`에 `FileModes.WORLD_READABLE`(`0644`) 생성 속성만 전달했기 때문에 POSIX 커널이 호출자 `umask`로 권한을 마스킹하여 설치된 JAR와 렌더링된 설정 파일이 `0600`(`rw-------`)으로 생성되고 비루트 `agent-ledger-mcp` 서비스 계정이 파일을 읽지 못하는 문제가 있었습니다. 모든 MCP 도구 계약, 증명 프로토콜, 데이터베이스 스키마, CLI 옵션이 `3.0.0`과 하위 호환을 유지하므로 패치 버전을 `3.0.0`에서 `3.0.1`로 올렸습니다.

### 호환되지 않는 변경

이 릴리스에는 호환되지 않는 변경이 없습니다. 기존 `3.0.0` MCP 클라이언트, 클라이언트 훅, 데이터베이스 스키마(`V11`), 설정 파일, 서비스 유닛은 수정 없이 그대로 동작합니다.

### 이전 절차

1. `./gradlew assemble`(시험 데이터베이스 불필요)로 `3.0.1` JAR를 빌드하거나 릴리스 JAR(`ledger-cli.jar`, `ledger-mcp-server.jar`, `ledger-admin-web.jar`)를 준비합니다.
2. 롤백 시 파일 복사와 서비스 재시작만으로 복구할 수 있도록 `/opt/agent-ledger-mcp/` 아래 현재 설치된 `3.0.0` JAR를 먼저 백업합니다.
3. 기존 옵션 그대로 `3.0.1` JAR 디렉터리를 지정해 `deploy/install.sh`(Linux) 또는 `deploy\install.cmd`(Windows)를 다시 실행합니다. 스키마는 `V11` 그대로이므로 추가 데이터베이스 마이그레이션은 실행되지 않습니다.
4. 두 `/healthz` 엔드포인트(`127.0.0.1:8765/healthz`, `127.0.0.1:8865/healthz`)가 `UP`을 반환하는지 확인합니다.
5. 되돌리려면 백업해 둔 `3.0.0` JAR를 복원하고 `agent-ledger-mcp`와 `agent-ledger-mcp-admin` 서비스를 재시작합니다.

### 추가

- **POSIX `umask 077` 회귀 시험 (`DeployFilesUmaskTest`)**: `umask 077` 하위 JVM 프로세스를 실행해 `Files.createTempFile`에 `FileModes.WORLD_READABLE`만 전달한 대조 파일이 `rw-------`(`0600`)으로 마스킹됨을 확인하고, 같은 조건에서 `DeployFiles.replace`가 복사한 JAR와 렌더링한 설정 파일을 정확한 `rw-r--r--`(`0644`) 권한으로 생성함을 검증하는 회귀 시험 및 크로스 플랫폼 임시 파일 정리 시험을 추가했습니다.

### 변경

- **`DeployFiles.replace`의 `0644` 권한 명시 적용**: `prepare-host`와 `render-deploy`의 원자적 이름 바꾸기 직전에 임시 파일에 `FileModes.apply`로 `FileModes.WORLD_READABLE`(`rw-r--r--`)를 명시 적용해, 호출자 `umask`와 무관하게 `/opt/agent-ledger-mcp/` 아래 JAR, `/etc/agent-ledger-mcp/` 아래 렌더링 설정 파일, systemd 유닛 파일을 `agent-ledger-mcp` 서비스 계정이 항상 읽을 수 있도록 수정했습니다.
- **버전 정렬**: Gradle 빌드, MCP 서버 메타데이터, 클라이언트 플러그인 매니페스트 버전을 `3.0.1`로 정렬했습니다.

### 제거

이 릴리스에서 제거된 기능, 엔드포인트, CLI 명령, MCP 도구 또는 설정은 없습니다.

### 보안

- `DeployFiles.replace`는 느슨한 `umask`에서도 더 넓은 권한으로 파일이 생성되지 않도록 임시 파일 생성 시 `FileModes.WORLD_READABLE`를 계속 전달하며, `FileModes.apply`는 권한 변경 전 `LinkOption.NOFOLLOW_LINKS`로 심볼릭 링크를 거부합니다.
- 비밀 디렉터리, 첨부 키, 첨부 저장소의 소유자 전용 제한 권한은 그대로 유지되며 이 변경의 영향을 받지 않습니다.

### 요구 사항

- 서버 호스트 및 클라이언트 훅 호스트의 Java 25 런타임(`JDK 25`).
- 기존 `3.0.0` PostgreSQL 데이터베이스(스키마 `V11`) 및 등록된 JDBC 드라이버. 새로운 의존성은 추가되지 않습니다.

### 알려진 제한

- `DeployFilesUmaskTest`의 `umask 077` 하위 프로세스 시험은 POSIX 파일 시스템(Linux CI)에서 실행되며, Windows 호스트는 POSIX `umask` 대신 디렉터리 ACL로 접근 제어를 적용합니다.
