# veridger 4.3.1

## English

### Summary

`4.3.1` is a comprehensive security hardening patch release across the Admin Web, MCP server, application and database layers, CLI deployment platform, client hooks, and host updaters. It introduces `Schema-Version: V13` (`V13__owner_passkey_counter.sql`) to persist WebAuthn `signatureCount` monotonically without mutating the append-only `owner_passkey` table, closes the merged-issue self-verification bypass in `TransitionOperation`, replaces the Spring AI Streamable HTTP transport with `BoundedStreamableServerTransportProvider`, isolates service-writable files under `<etc>/driver-state` and `<etc>/update` so `<etc>` is read-only to the service account, eliminates TOCTOU symlink and downgrade risks in `veridger-updater.sh` and `veridger-updater.cmd`, and hardens input, charset, header, and stdin boundaries across all modules.

### Breaking changes

There are no breaking MCP tool, REST API, or client hook protocol changes. Because `4.3.1` advances the database schema to `Schema-Version: V13` (`owner_passkey_counter`), installations upgrading from `4.3.0` (`Schema-Version: V12`) must run `ledger-cli migrate` (and re-run `install.sh` or `install.cmd` to apply the updated host directory permissions and updater scripts) rather than using the Admin Web one-click `/updates` button.

### Migration

1. Build the `4.3.1` jars with `./gradlew assemble` or download and verify `SHA256SUMS` from the `4.3.1` release.
2. Run `ledger-cli migrate` as the database DDL owner account to apply `V13__owner_passkey_counter.sql` and grant `SELECT, INSERT, UPDATE` on `owner_passkey_counter` to the application account.
3. Re-run `deploy/install.sh` (Linux) or `deploy/install.cmd` (Windows) so `<etc>` becomes read-only to the service account, `<etc>/driver-state` and `<etc>/update` are provisioned, and the hardened `veridger-updater.sh` or `veridger-updater.cmd` is installed.
4. Verify `/healthz` on the MCP server and Admin Web, and update client hooks with `deploy/install-hook.sh` or `deploy/install-hook.cmd`.
5. Roll back by restoring the `4.3.0` JARs; `owner_passkey_counter` is additive and ignored by `4.3.0`.

### New

- **Monotonic WebAuthn counter table (`V13__owner_passkey_counter.sql`)**: Added `owner_passkey_counter` alongside the append-only `owner_passkey` table and updated `PasskeyRepository` and `PasskeyService` so hardware authenticator `signatureCount` advances monotonically and rollback or cloned assertions are rejected across restarts.
- **Hardened Streamable HTTP transport (`BoundedStreamableServerTransportProvider`)**: Replaced the final Spring AI transport with a Veridger-owned `McpStreamableServerTransportProvider` enforcing atomic `maxSessions` admission, fast sub-interval idle eviction driven by `Clock`, and SSE-only keep-alive probing with active `onPingFailure` stream cleanup.
- **Isolated writable subdirectories (`<etc>/driver-state`, `<etc>/update`)**: Added `DeployLayout.driverStateDirectory()` and `DeployLayout.updateDirectory()` so `jdbc-driver.yaml` and staged updates live in dedicated service-writable directories while `<etc>` (`application.yaml`, `local.yaml`) stays read-only to the service account.

### Changed

- **Merged-issue self-verification closure (`TransitionOperation`)**: `reporters()` now inspects the entire merged source set (current owner, historical owners, editors, resolvers, creator, and case recorders) so no contributor on a merged source issue can self-verify the root issue (`SAME_SESSION`).
- **Exact-case authorization and receipt verification (`PasskeyRepository`, `GrantStateRepository`, `GrantService`, `ReceiptService`)**: Added Java exact-case checks on credential IDs, active grant keys, author IDs, and operation keys to remain safe on case-insensitive database collations.
- **Large `IN` clause chunking (`EntityLookupRepository`, `MergeChainRepository`)**: Chunked multi-ID SQL `IN` lookups into batches of 500 to prevent database parameter-limit DoS.
- **Reserved owner identity & attachment upload hardening (`AuthorId`, `Authors`, `AuthorAttestationVerifier`, `UploadService`, `AttachmentFlow`, `AttachmentStore`)**: Rejected `user:owner` and `user:*` in session attestation and grant APIs, enforced live-grant checks on unsigned `uploadId` reads, included encryption overhead in disk-space reservations, cleaned up orphaned chunk files on `recordChunk` failure, and guarded `AttachmentStore.read()` against `long` overflow.
- **MCP and Admin Web HTTP boundary hardening (`McpSecurityConfiguration`, `TransportOriginAuthorization`, `McpWebConfiguration`, `McpHttpExceptionAdvice`, `RequestSizeFilter`, `AdminHttpExceptionAdvice`, `GitHubReleaseClient`, `FileUpdateQueue`, `Paging`)**: Gated `/healthz` with `TransportOriginAuthorization` and rejected duplicate `Origin` headers, scoped MCP `RequestSizeFilter` strictly to `/mcp`, returned `application/problem+json` on `413` regardless of `Accept`, rejected invalid request charsets cleanly, caught malformed `Accept` headers in `AdminHttpExceptionAdvice`, bounded GitHub release metadata to 4 MiB and HTTPS port 443, enforced non-symlink regular-file checks in `FileUpdateQueue`, and capped `Paging` history trails at 200 entries.
- **Host updater, installer, Windows ACL, and hook stdin hardening (`veridger-updater.sh`, `veridger-updater.cmd`, `install.sh`, `install.cmd`, `install-hook.sh`, `install-hook.cmd`, `WindowsPlatform`, `WindowsAccess`, `ClientCommand`, `HookCli`)**: Added FD-pinned `O_NOFOLLOW` operations on Linux and dangling-reparse checks on Windows, enforced monotonic version floors via `.installed-version`, enforced HTTPS-only redirects (`--proto-redir '=https'`), added `WindowsAccess.requireTrustedOwner` against pre-created `C:\ProgramData` squatting, hardened `install.cmd` (`DisableDelayedExpansion`, GUID temp dirs, port parsing), stopped existing services before Linux upgrade preparation, and capped hook stdin reads at 32 MiB.

### Removed

No MCP tools, REST endpoints, CLI commands, database tables, or configuration properties were removed in this release.

### Security

- Closes all confirmed High, Medium, and Low findings from the `4.3.1` full-codebase security audit across `ledger-admin-web`, `ledger-mcp-server`, `ledger-application`, `ledger-database`, `ledger-cli`, `ledger-client-hook`, `ledger-hook-client`, and `deploy/*`.
- Preserves backward-compatible `spring.config.import` ordering (`<etc>/jdbc-driver.yaml` followed by `<etc>/driver-state/jdbc-driver.yaml`) so existing installations continue booting smoothly during transition.

### Requirements

- Java 25 runtime (`JDK 25`) on server and client hosts.
- Database on `Schema-Version: V13` (run `ledger-cli migrate` before starting `4.3.1`).
- Linux host updater requires `python3`, `curl`, and `sha256sum`.

### Known limitations

- Existing `4.3.0` hosts using one-click `/updates` will see `SCHEMA_MIGRATION_REQUIRED` because `4.3.1` requires `Schema-Version: V13`; perform the migration and installer re-run once to enable hardened one-click updates for subsequent `V13` patch releases.

## 한국어

### 요약

`4.3.1`은 관리 웹, MCP 서버, 애플리케이션·데이터베이스 계층, CLI 배포 플랫폼, 클라이언트 훅 및 호스트 업데이터 전반을 강화한 종합 보안 패치 릴리스입니다. 추가 전용 `owner_passkey` 테이블을 변경하지 않고 WebAuthn `signatureCount`를 단조 증가 저장하도록 `Schema-Version: V13`(`V13__owner_passkey_counter.sql`)을 도입했고, `TransitionOperation`의 병합 이슈 자기검수 우회를 차단했으며, Spring AI Streamable HTTP 전송 계층을 `BoundedStreamableServerTransportProvider`로 교체했습니다. 또한 `<etc>`를 서비스 계정에 읽기 전용으로 잠그고 쓰기 상태를 `<etc>/driver-state`와 `<etc>/update`로 격리했으며, `veridger-updater.sh`와 `veridger-updater.cmd`의 TOCTOU 심볼릭 링크·다운그레이드 위험을 제거하고 전 모듈의 입력·문자셋·헤더·표준입력 경계를 보강했습니다.

### 호환되지 않는 변경

MCP 도구, REST API 또는 클라이언트 훅 프로토콜의 호환성 파괴 변경은 없습니다. 다만 `4.3.1`은 데이터베이스 스키마를 `Schema-Version: V13`(`owner_passkey_counter`)으로 올리므로, `4.3.0`(`Schema-Version: V12`)에서 업그레이드할 때는 관리 웹의 원클릭 `/updates` 대신 `ledger-cli migrate`를 실행하고 `install.sh` 또는 `install.cmd`를 다시 실행해 강화된 디렉터리 권한과 업데이터 스크립트를 적용해야 합니다.

### 이전 절차

1. `./gradlew assemble`로 `4.3.1` JAR를 빌드하거나 `4.3.1` 릴리스에서 내려받아 `SHA256SUMS`를 검증합니다.
2. 데이터베이스 DDL 소유자 계정으로 `ledger-cli migrate`를 실행해 `V13__owner_passkey_counter.sql`을 적용하고 애플리케이션 계정에 `owner_passkey_counter`의 `SELECT, INSERT, UPDATE` 권한을 부여합니다.
3. `deploy/install.sh`(Linux) 또는 `deploy/install.cmd`(Windows)를 다시 실행해 `<etc>`를 서비스 계정 읽기 전용으로 전환하고 `<etc>/driver-state`, `<etc>/update` 및 강화된 `veridger-updater.sh` 또는 `veridger-updater.cmd`를 설치합니다.
4. MCP 서버와 관리 웹의 `/healthz`를 확인하고, `deploy/install-hook.sh` 또는 `deploy/install-hook.cmd`로 클라이언트 훅을 갱신합니다.
5. 롤백 시 `4.3.0` JAR를 복원하면 되며 `owner_passkey_counter`는 추가 테이블이므로 `4.3.0`이 무시합니다.

### 추가

- **단조 증가 WebAuthn 카운터 테이블 (`V13__owner_passkey_counter.sql`)**: 추가 전용 `owner_passkey` 옆에 `owner_passkey_counter`를 추가하고 `PasskeyRepository`와 `PasskeyService`를 갱신해 하드웨어 인증기의 `signatureCount`가 단조 증가 저장되며 재시작 후에도 카운터 역행·복제 어서션이 차단되도록 했습니다.
- **강화된 Streamable HTTP 전송 계층 (`BoundedStreamableServerTransportProvider`)**: final 클래스인 Spring AI 전송 계층을 자체 `McpStreamableServerTransportProvider`로 교체해 원자적 `maxSessions` 수용, `Clock` 기반 빠른 유휴 세션 회수, 그리고 `onPingFailure` 정리와 함께 SSE 전용 keep-alive 프로브를 적용했습니다.
- **서비스 쓰기 전용 하위 디렉터리 격리 (`<etc>/driver-state`, `<etc>/update`)**: `DeployLayout.driverStateDirectory()`와 `DeployLayout.updateDirectory()`를 추가해 `jdbc-driver.yaml`과 스테이징 업데이트가 전용 디렉터리에만 쓰이도록 하고 `<etc>`(`application.yaml`, `local.yaml`)는 서비스 계정에 읽기 전용으로 유지합니다.

### 변경

- **병합 이슈 자기검수 차단 (`TransitionOperation`)**: `reporters()`가 병합된 원본 이슈 전체의 현재 소유자, 과거 소유자, 편집자, 해결자, 생성자, 사례 기록자를 모두 수집하도록 수정해 원본 기여자가 대표 이슈를 자기검수(`SAME_SESSION`)하지 못하게 막았습니다.
- **대소문자 정확 일치 인가 및 영수증 검증 (`PasskeyRepository`, `GrantStateRepository`, `GrantService`, `ReceiptService`)**: 대소문자를 구분하지 않는 DB 콜레이션 환경에서도 안전하도록 자격 증명 ID, 활성 부여 키, 작성자 ID, 작업 키에 Java 정확 일치 검사를 추가했습니다.
- **대량 `IN` 절 청크 분할 (`EntityLookupRepository`, `MergeChainRepository`)**: 다건 ID 조회의 SQL `IN` 절을 500건 단위로 분할해 DB 바인드 파라미터 한도 초과 DoS를 방지했습니다.
- **예약 소유자 신원 및 첨부 업로드 강화 (`AuthorId`, `Authors`, `AuthorAttestationVerifier`, `UploadService`, `AttachmentFlow`, `AttachmentStore`)**: 세션 증명 및 권한 부여 API에서 `user:owner`·`user:*` 사용을 거부하고, 미서명 `uploadId` 조회 시 활성 부여를 검증하며, 디스크 여유 공간 계산에 암호화 오버헤드를 반영하고, `recordChunk` 실패 시 고아 청크 파일을 정리하며 `AttachmentStore.read()`의 `long` 오버플로를 방지했습니다.
- **MCP 및 관리 웹 HTTP 경계 강화 (`McpSecurityConfiguration`, `TransportOriginAuthorization`, `McpWebConfiguration`, `McpHttpExceptionAdvice`, `RequestSizeFilter`, `AdminHttpExceptionAdvice`, `GitHubReleaseClient`, `FileUpdateQueue`, `Paging`)**: `/healthz`에 `TransportOriginAuthorization`을 적용하고 중복 `Origin` 헤더를 거부했으며, MCP `RequestSizeFilter`를 `/mcp`로 한정하고 `Accept` 값과 무관하게 `413`에서 `application/problem+json`을 반환하도록 했습니다. 또한 잘못된 문자셋을 안전하게 거부하고 `AdminHttpExceptionAdvice`에서 비정상 `Accept` 헤더를 처리하며, GitHub 릴리스 메타데이터를 4 MiB 및 HTTPS 포트 443으로 제한하고, `FileUpdateQueue`의 비심볼릭 정규 파일 검사를 강화했으며, `Paging` 뒤로가기 이력을 200건으로 제한했습니다.
- **호스트 업데이터·설치기·Windows ACL·훅 표준입력 강화 (`veridger-updater.sh`, `veridger-updater.cmd`, `install.sh`, `install.cmd`, `install-hook.sh`, `install-hook.cmd`, `WindowsPlatform`, `WindowsAccess`, `ClientCommand`, `HookCli`)**: Linux에 FD 고정 `O_NOFOLLOW` 연산, Windows에 댕글링 리파스 포인트 검사를 도입하고, `.installed-version` 기반 단조 버전 하한과 HTTPS 전용 리다이렉트(`--proto-redir '=https'`)를 강제했습니다. 또한 `C:\ProgramData` 선점 공격을 막는 `WindowsAccess.requireTrustedOwner`를 추가하고, `install.cmd`를 강화(`DisableDelayedExpansion`, GUID 임시 디렉터리, 포트 파싱)했으며, Linux 업그레이드 준비 전 기존 서비스 중지와 훅 표준입력 32 MiB 상한을 적용했습니다.

### 제거

이 릴리스에서 제거된 MCP 도구, REST 엔드포인트, CLI 명령, 데이터베이스 테이블 또는 설정 항목은 없습니다.

### 보안

- `4.3.1` 전수 보안 감사에서 확인된 `ledger-admin-web`, `ledger-mcp-server`, `ledger-application`, `ledger-database`, `ledger-cli`, `ledger-client-hook`, `ledger-hook-client`, `deploy/*` 전반의 High·Medium·Low 취약점을 모두 패치했습니다.
- 기존 설치 환경이 전환 중에도 문제없이 기동하도록 `spring.config.import` 순서(`<etc>/jdbc-driver.yaml` 다음 `<etc>/driver-state/jdbc-driver.yaml`)의 하위 호환성을 유지했습니다.

### 요구 사항

- 서버 호스트 및 클라이언트 호스트의 Java 25 런타임(`JDK 25`).
- `Schema-Version: V13` 데이터베이스(`4.3.1` 기동 전 `ledger-cli migrate` 실행 필요).
- Linux 호스트 업데이터는 `python3`, `curl`, `sha256sum`이 필요합니다.

### 알려진 제한

- 기존 `4.3.0` 호스트의 원클릭 `/updates` 화면에서는 `4.3.1`이 `Schema-Version: V13`을 요구하므로 `SCHEMA_MIGRATION_REQUIRED`로 표시됩니다. 마이그레이션과 설치기 재실행을 1회 완료하면 이후 `V13` 패치 릴리스부터 강화된 원클릭 업데이트를 사용할 수 있습니다.
