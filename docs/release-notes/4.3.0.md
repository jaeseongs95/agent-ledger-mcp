# veridger 4.3.0

## English

### Summary

`4.3.0` is a backward-compatible minor release that overhauls the Admin Web UI/UX across every page while preserving `Schema-Version: V12` and keeping `/api/overview` JSON and all MCP tool contracts unchanged. It eliminates table column crushes and character-by-character wrapping (including replacing cramped deliverables tables with responsive cards), adds a `taskId` filter to Issues, localizes all enum and common-code labels in Korean and English across every filter, badge, and cell, redesigns Overview (`GET /`) into a Focused Governance Cockpit with hydrated attention details, renames and upgrades Milestone Criteria (`GET /criteria`) into a Release Gates hub with per-milestone progress rollups, linked-work counts, and a dedicated detail page (`GET /criteria/detail`), and replaces inline raw history diffs with readable change lines plus a native `<dialog>` JSON viewer.

### Breaking changes

There are no breaking API, database schema, MCP tool, CLI, or client hook changes in this release. `4.3.0` runs on `Schema-Version: V12`, so `4.2.0` installations can upgrade directly (including from the Admin Web `/updates` page) without running `ledger-cli migrate`.

### Migration

1. Build the `4.3.0` jars with `./gradlew assemble` or update directly from `/updates` (or download and verify `SHA256SUMS` from the `4.3.0` release).
2. If upgrading from `4.2.0` (`Schema-Version: V12`), replace the server JARs and restart both services; no database migration is required.
3. Verify `/healthz` on the MCP server and Admin Web.
4. Roll back by restoring the `4.2.0` JARs; no database changes were made.

### New

- **Issues `taskId` filter**: Added `taskId` filtering to `IssueQueryRepository`, `ListService`, `IssuesController`, and `GET /issues` using ANSI `EXISTS` over the `ix_issue_task_task` index.
- **Unified localized labels (`Labels`)**: Added the `Labels` console component and complete English/Korean bundles (`admin.properties`, `admin_ko.properties`) so every filter dropdown, badge, operation, entity type, scope, and common code displays its localized name while preserving canonical wire tokens in form values and URLs.
- **Release Gates hub and detail page (`GET /criteria`, `GET /criteria/detail`)**: Added per-milestone readiness rollups and batched linked-work counts in `CriterionQueryRepository` and `ListService`, clickable milestone progress cards, a milestone filter dropdown, 3-step onboarding for empty projects, and a dedicated `GET /criteria/detail` page with full linked issues, specifications, tasks, and recent history.
- **Native `<dialog>` History JSON viewer**: Replaced inline `<details>` raw JSON dumps on `GET /history` with concise field-change lines (supporting `[old, new]` diff arrays) and a native `<dialog>` modal with pretty-printed JSON, row metadata, copy button, Escape/backdrop dismissal, and focus restoration in `admin-ui.js`.

### Changed

- **Overview (`GET /`) Focused Governance Cockpit**: Replaced static lifetime KPIs with four live action tiles (Needs verification, Hygiene & anomalies, Active work, Blocked & disputed), moved MCP status to a quiet header pill that expands into a danger banner only when down, hydrated attention rows with title, owner, and updated timestamp, and grouped Work & gate breakdown cards showing only non-zero localized pills while leaving `/api/overview` JSON untouched.
- **Table readability and responsive deliverable cards (`admin.css`)**: Replaced aggressive `overflow-wrap: anywhere` rules that crushed columns into vertical strips with explicit column width guards, non-wrapping badges/operations/timestamps, and responsive deliverable cards across issue, specification, and task detail pages.
- **Release gates navigation and links**: Renamed navigation and headings to Release gates, added a Release gates quick link on Projects, and turned criterion references on issue, specification, task, and history pages into clickable links to `GET /criteria/detail`.

### Removed

No API endpoints, MCP tools, CLI commands, database tables, or configuration properties were removed in this release.

### Security

- All UI changes preserve strict CSP compliance (`3.8`): zero inline scripts, zero inline event handlers, and zero inline style attributes across all templates (progress bars use native HTML elements styled in `admin.css`).
- Evidence URLs inside responsive deliverable cards continue to render as links only for `http://` and `https://` schemes; all other text remains escaped.

### Requirements

- Java 25 runtime (`JDK 25`) on server and client hosts.
- Database on `Schema-Version: V12` (run `ledger-cli migrate` only if upgrading from `4.1.0` or earlier).

### Known limitations

- On `GET /issues`, `taskId` performs an exact task ID match backed by `ix_issue_task_task` rather than a substring wildcard scan.
- On `GET /history`, the JSON diff modal requires JavaScript (`admin-ui.js`) for progressive enhancement; with JavaScript disabled, raw JSON remains visible in the cell.

## 한국어

### 요약

`4.3.0`은 `Schema-Version: V12`와 `/api/overview` JSON 및 모든 MCP 도구 계약을 그대로 유지하면서 관리 웹 전체 페이지의 UI/UX를 개편한 하위 호환 마이너 릴리스입니다. 표 열 찌그러짐과 글자 단위 세로 줄바꿈을 근본 수정하고(좁은 산출물 표를 반응형 카드로 교체), 이슈 화면에 `taskId` 검색 조건을 추가했으며, 모든 필터·배지·셀의 열거형 및 공통코드 표기를 한국어/영어 설정에 맞게 통일했습니다. 또한 개요(`GET /`)를 조치·검증 중심의 거버넌스 콕핏으로 재구성하고, 마일스톤 기준(`GET /criteria`)을 출시 기준 허브(마일스톤별 진행률 카드, 연결 작업 수, 상세 페이지 `GET /criteria/detail`)로 개편했으며, 이력(`GET /history`)의 원본 JSON을 읽기 쉬운 변경 요약과 네이티브 `<dialog>` 팝업으로 전환했습니다.

### 호환되지 않는 변경

이 릴리스에는 호환되지 않는 API, 데이터베이스 스키마, MCP 도구, CLI 또는 클라이언트 훅 변경이 없습니다. `4.3.0`은 `Schema-Version: V12`에서 그대로 동작하므로 `4.2.0` 설치 환경은 `ledger-cli migrate` 없이 관리 웹 `/updates` 페이지에서 바로 업그레이드할 수 있습니다.

### 이전 절차

1. `./gradlew assemble`로 `4.3.0` JAR를 빌드하거나 `/updates`에서 바로 업데이트(또는 `4.3.0` 릴리스에서 내려받아 `SHA256SUMS` 검증)합니다.
2. `4.2.0`(`Schema-Version: V12`)에서 업그레이드하는 경우 서버 JAR를 교체하고 두 서비스를 재시작하면 되며 별도 데이터베이스 마이그레이션은 필요하지 않습니다.
3. MCP 서버와 관리 웹의 `/healthz`를 확인합니다.
4. 롤백 시 `4.2.0` JAR를 복원하면 되며 데이터베이스 변경 사항은 없습니다.

### 추가

- **이슈 `taskId` 검색 필터**: `IssueQueryRepository`, `ListService`, `IssuesController`, `GET /issues`에 `ix_issue_task_task` 인덱스를 활용하는 ANSI `EXISTS` 기반 `taskId` 검색 조건을 추가했습니다.
- **통합 다국어 코드·상태 라벨 (`Labels`)**: `Labels` 콘솔 컴포넌트와 한/영 메시지 번들(`admin.properties`, `admin_ko.properties`)을 보강해 모든 필터 드롭다운, 배지, 작업 종류, 대상 종류, 권한 범위, 공통코드가 언어 설정에 맞는 이름으로 표시되도록 하고 폼 값과 URL에는 정규 코드 토큰을 유지했습니다.
- **출시 기준 허브 및 상세 페이지 (`GET /criteria`, `GET /criteria/detail`)**: `CriterionQueryRepository`와 `ListService`에 마일스톤별 충족률 집계와 연결 항목 수 일괄 조회를 추가하고, 클릭 가능한 마일스톤 진행률 카드, 마일스톤 드롭다운 필터, 빈 프로젝트용 3단계 온보딩, 연결 이슈·명세·작업·최근 이력을 보여 주는 `GET /criteria/detail` 상세 페이지를 추가했습니다.
- **네이티브 `<dialog>` 이력 원본 JSON 팝업**: `GET /history`의 인라인 `<details>` 원본 JSON 표시를 `[old, new]` 배열 diff를 해석하는 간결한 변경 요약과 `admin-ui.js` 기반 네이티브 `<dialog>` 팝업(정렬된 JSON, 행 메타데이터, 복사 버튼, ESC/배경 닫기, 포커스 복원)으로 교체했습니다.

### 변경

- **개요(`GET /`) 거버넌스 콕핏 재설계**: 누적 총량 카드를 4개의 실시간 조치 타일(검증 대기, 장부 이상 항목, 진행 중 작업, 차단·분쟁·미달)로 교체하고, MCP 서버 상태는 평소 헤더의 간결한 배지로 표시하되 중단 시에만 경고 배너로 확장했습니다. 조치 대기 표에는 제목·담당자·갱신 시각을 일괄 조회해 표시하고, 분포 카드에는 0이 아닌 항목만 다국어 라벨로 표시하며 `/api/overview` JSON 계약은 변경하지 않았습니다.
- **표 가독성 개선 및 반응형 산출물 카드 (`admin.css`)**: 열을 세로로 찌그러뜨리던 `overflow-wrap: anywhere` 규칙을 교정하고, 배지·작업 종류·시각의 줄바꿈 방지와 최소 너비 가드를 적용했으며, 이슈·명세·작업 상세의 산출물 표를 반응형 카드로 교체했습니다.
- **출시 기준 메뉴명 및 링크 정비**: 메뉴와 제목을 출시 기준으로 정리하고 프로젝트 목록에 출시 기준 바로가기를 추가했으며, 이슈·명세·작업·이력 화면의 출시 기준 ID를 `GET /criteria/detail` 링크로 연결했습니다.

### 제거

이 릴리스에서 제거된 API 엔드포인트, MCP 도구, CLI 명령, 데이터베이스 테이블 또는 설정 항목은 없습니다.

### 보안

- 모든 UI 개편은 엄격한 CSP 규칙(`3.8`)을 준수합니다. 모든 템플릿에 인라인 스크립트, 인라인 이벤트 핸들러, 인라인 스타일 속성이 없으며 진행률 막대도 `admin.css`로 스타일링된 기본 HTML 요소를 사용합니다.
- 반응형 산출물 카드의 근거 URL도 기존과 동일하게 `http://`와 `https://` 스킴만 링크로 렌더링하고 나머지 텍스트는 안전하게 이스케이프합니다.

### 요구 사항

- 서버 호스트 및 클라이언트 호스트의 Java 25 런타임(`JDK 25`).
- `Schema-Version: V12` 데이터베이스(`4.1.0` 이하에서 업그레이드할 때만 `ledger-cli migrate` 실행 필요).

### 알려진 제한

- `GET /issues`의 `taskId` 필터는 부분 일치 스캔 대신 `ix_issue_task_task` 인덱스를 사용하는 정확한 작업 ID 일치 조건으로 동작합니다.
- `GET /history`의 원본 JSON 팝업은 점진적 향상(`admin-ui.js`)으로 동작하며, 자바스크립트가 비활성화된 환경에서는 셀에 원본 JSON이 그대로 표시됩니다.
