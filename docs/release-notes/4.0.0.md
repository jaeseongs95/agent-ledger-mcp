# agent-ledger-mcp 4.0.0

## English

### Summary

`4.0.0` removes four redundant authentication ceremonies while preserving the internet-facing perimeter security of both the MCP server and the admin console. Once the owner signs in to `ledger-admin-web`, owner changes apply directly under session and CSRF protection without per-action passkey re-approval, and granting project scopes to a session ID (`<vendor>:<session_id>`) requires neither per-session Bearer token issuance nor Ed25519 public-key registration. This release also includes the POSIX `umask 077` deployment permission fix in `DeployFiles.replace` and resident client-hook startup concurrency fixes in `OwnerOnlyFiles` and `AddressFile`. Because the `_hostAttestation` wire format, removed CLI commands, removed admin endpoints, and MCP bearer authentication rules break compatibility with `3.0.0` clients and hooks, the major version increases from `3.0.0` to `4.0.0`.

### Breaking changes

- **Plain `<vendor>:<session_id>` `_hostAttestation` format**: In `3.0.0`, `ledger-client-hook` signed each tool call with an Ed25519 session key (`ala3.<payload>.<signature>`) and `ledger-mcp-server` verified signatures against `session_public_key`. In `4.0.0`, `ledger-client-hook` stamps `_hostAttestation` as `<vendor>:<session_id>` (rejecting any agent-supplied `_hostAttestation` with `RESERVED_FIELD`), and `ledger-mcp-server` validates the `<vendor>:<session_id>` format and checks `session_grant` directly. Update `ledger-client-hook.jar` together with `ledger-mcp-server.jar` so old signed tokens are no longer sent.
- **Single MCP perimeter token (`ledger.mcp.token` only)**: In `3.0.0`, `/mcp` accepted per-session `lgt_...` Bearer tokens in addition to `ledger.mcp.token`, controlled by `ledger.mcp.auth-mode`. In `4.0.0`, `/mcp` authenticates HTTP requests solely with the configured constant-time `ledger.mcp.token`, and `ledger.mcp.auth-mode` and `ledger.attestation.window` are removed. Clients that previously sent per-session `lgt_...` tokens must switch their `Authorization: Bearer` header to `ledger.mcp.token`.
- **Removed session key and session token CLI commands and admin endpoints**: `ledger-cli` no longer provides `key-register`, `key-revoke`, `token-issue`, `token-revoke`, or `token-list`; `ledger-client-hook` no longer provides `session-key`; and `ledger-admin-web` no longer exposes `/grants/preview`, `/grants/token`, `/grants/token/revoke`, `/grants/key/revoke`, or `/approval/intent`. Grant permissions directly via `POST /grants/author`, `POST /grants/sync`, or `ledger-cli grant`.

### Migration

1. Build the `4.0.0` jars with `./gradlew assemble` (no test database required) or obtain the release jars (`ledger-cli.jar`, `ledger-mcp-server.jar`, `ledger-admin-web.jar`, `ledger-client-hook.jar`, `ledger-hook-client.jar`).
2. Back up the currently installed `3.0.0` jars under `/opt/agent-ledger-mcp/` before replacing them so rollback is a single file copy and service restart.
3. Remove any obsolete `ledger.mcp.auth-mode` or `ledger.attestation.window` entries from `/etc/agent-ledger-mcp/` configuration files if present, and ensure MCP clients send `ledger.mcp.token` in the `Authorization: Bearer` header.
4. Re-run `deploy/install.sh` (Linux) or `deploy\install.cmd` (Windows) with the `4.0.0` jars directory and existing options; no database migration runs because the schema remains at `V11`.
5. Replace `ledger-client-hook.jar` and `ledger-hook-client.jar` in every client hook installation (Claude Code, Codex, Antigravity) and stop any running resident hook process so the new `4.0.0` hook jar starts cleanly.
6. Verify both `/healthz` endpoints (`127.0.0.1:8765/healthz` and `127.0.0.1:8865/healthz`) return `UP`, then confirm that a granted session succeeds on `ledger_whoami` and write calls without registering a key or issuing a session token.
7. To roll back, restore the backed-up `3.0.0` server and client-hook jars, restore any removed `3.0.0` configuration properties, and restart `agent-ledger-mcp` and `agent-ledger-mcp-admin`.

### New

- **Direct `<vendor>:<session_id>` author verifier (`AuthorAttestationVerifier`)**: Validates host-stamped `<vendor>:<session_id>` values directly against `ActorId` rules (`HOST_ATTESTATION_REQUIRED`, `AUTHOR_ID_FORMAT`) without Ed25519 key lookup or timestamp windows.
- **Streamlined 1-click session grant workflow in `ledger-admin-web`**: Owners grant, edit, or revoke project scopes directly by session ID (`POST /grants/author`, `POST /grants/sync`, `POST /grants/revoke`) immediately after signing in.
- **POSIX `umask 077` regression coverage (`DeployFilesUmaskTest`)**: Spawns a child JVM under `umask 077` to verify that `DeployFiles.replace` enforces exact `rw-r--r--` (`0644`) permissions for copied jars and rendered configuration files.
- **Resident hook concurrency regression tests (`OwnerOnlyFilesTest`, `AddressFileTest`)**: Verifies concurrent directory creation and concurrent polling-read/atomic-replace behavior on Windows and POSIX hosts.

### Changed

- **Direct owner writes after sign-in in `ledger-admin-web`**: Signing in once with Passkey (`PASSKEY`), OpenID Connect (`OIDC`), or Admin Token (`TOKEN`) authorizes subsequent owner mutations protected by CSRF tokens and `SameSite=Strict` session cookies, without re-prompting for a WebAuthn passkey on every button click. Passkeys and `passkey-code` remain supported for console sign-in.
- **Simplified `ledger-client-hook` stamping**: The `PreToolUse` hook stamps `_hostAttestation` with `<vendor>:<session_id>` directly without creating or reading local Ed25519 key files, while continuing to reject agent-supplied `_hostAttestation` (`RESERVED_FIELD`).
- **Explicit `0644` mode enforcement in `DeployFiles.replace`**: Applies `FileModes.apply` with `FileModes.WORLD_READABLE` (`rw-r--r--`) immediately before atomic rename in `prepare-host` and `render-deploy`, ensuring jars and rendered configuration files are readable by the `agent-ledger-mcp` service user even under `umask 077`.
- **Resident hook startup race fixes (`OwnerOnlyFiles.createDirectories`, `AddressFile.write`)**: Uses a single `BasicFileAttributes` check to avoid spurious `FileAlreadyExistsException` under concurrent first calls, and uses `StandardCopyOption.ATOMIC_MOVE` with `StandardCopyOption.REPLACE_EXISTING` and bounded retry on transient `AccessDeniedException` while clients poll the address file.
- **Version alignment**: Updated Gradle build, MCP server metadata, and client plugin manifests to `4.0.0`.

### Removed

- **Per-action passkey re-approval**: Removed `ApprovalInterceptor`, `ApprovalController`, `ApprovalService`, `ApprovalIntents`, `/approval/intent`, and client-side `data-approve` prompts. Replaced by 1-time owner sign-in plus Spring Security CSRF protection and `owner_audit` logging.
- **Per-session Bearer token authentication**: Removed `SessionTokenProvider`, `SessionTokenService`, `/grants/token`, `/grants/token/revoke`, and `ledger-cli` commands `token-issue`, `token-revoke`, and `token-list`. Replaced by the single constant-time MCP perimeter token `ledger.mcp.token`.
- **Per-session Ed25519 key ceremony**: Removed `SignedAttestationVerifier`, `AttestationProperties`, `AuthMode`, `SessionKeyService`, `ledger-client-hook` key store (`session-key`), `/grants/preview`, `/grants/key/revoke`, and `ledger-cli` commands `key-register` and `key-revoke`. Replaced by `AuthorAttestationVerifier` and direct `session_grant` authorization.

### Security

- **Hardened public-internet MCP perimeter**: `/mcp` now accepts only the configured constant-time `ledger.mcp.token` (`AgentTokenProvider`), preventing stale per-session database tokens from reaching the MCP endpoint. `StrictHttpFirewall` host allowlisting (`403`), `TransportOriginAuthorization` origin allowlisting (`403`), `RequestSizeFilter` (`413`), loopback binding (`127.0.0.1`), stateless sessions, `session_grant` scope enforcement, `Channel.REVIEWER` separation (`VERIFY_NEEDS_REVIEWER_LOGIN`), and hook `RESERVED_FIELD` anti-spoofing remain active.
- **Preserved admin console perimeter**: `ledger-admin-web` retains 1-time owner authentication (`PASSKEY` / `OIDC` / `TOKEN`), brute-force delay (`LoginAttempts` / `LoginDelay` / `PasskeyLoginGuard`), Spring Security CSRF tokens on every state-changing POST, `SameSite=Strict` + `HttpOnly` + `Secure` cookies with `sessionFixation().changeSessionId()`, Host allowlisting (`403`), strict CSP (`script-src 'self'`, `frame-ancestors 'none'`, `form-action 'self'`), and `owner_audit` recording.
- **Trust boundary change**: Because per-session Ed25519 signing is removed, any caller that possesses the shared `ledger.mcp.token` and knows a granted `<vendor>:<session_id>` can send that session identifier in `_hostAttestation`; treat `ledger.mcp.token` as a high-trust secret restricted to the owner's own client hosts and keep the client hook enabled so agents cannot forge `_hostAttestation` locally.
- **Deployment file permissions**: `DeployFiles.replace` continues to enforce `LinkOption.NOFOLLOW_LINKS` via `FileModes.apply`, and secret directories, attachment keys, and attachment storage retain owner-only permissions.

### Requirements

- Java 25 runtime (`JDK 25`) on the server host and client hook hosts.
- PostgreSQL database (schema `V11`) and registered JDBC driver; existing `3.0.0` databases require no schema migration.

### Known limitations

- Existing `session_public_key` and `session_token` database tables in schema `V11` are retained unused so Flyway-equivalent schema checksums and rollbacks to `3.0.0` remain intact.
- The `umask 077` child-process test in `DeployFilesUmaskTest` runs on POSIX file systems (verified on Linux CI); Windows hosts enforce access control through directory ACLs rather than POSIX `umask`.

## 한국어

### 요약

`4.0.0`은 MCP 서버와 관리 콘솔의 인터넷 노출 경계 보안은 유지하면서 불필요한 4가지 중복 인증 절차를 제거한 주 버전 릴리스입니다. 소유자가 `ledger-admin-web`에 한 번 로그인하면 세션과 CSRF 보호 아래에서 작업마다 패스키를 다시 승인하지 않고 바로 저장할 수 있으며, 세션 ID(`<vendor>:<session_id>`)에 프로젝트 권한을 부여할 때 세션별 Bearer 토큰 발급이나 Ed25519 공개키 등록을 거치지 않습니다. 또한 `DeployFiles.replace`의 POSIX `umask 077` 배포 권한 수정과 `OwnerOnlyFiles`, `AddressFile`의 상주 클라이언트 훅 동시성 수정이 함께 포함됩니다. `_hostAttestation` 전달 형식, 제거된 CLI 명령, 제거된 관리 웹 엔드포인트, MCP Bearer 인증 규칙이 `3.0.0` 클라이언트 및 훅과 호환되지 않으므로 주 버전을 `3.0.0`에서 `4.0.0`으로 올렸습니다.

### 호환되지 않는 변경

- **단순 `<vendor>:<session_id>` 형식의 `_hostAttestation`**: `3.0.0`에서는 `ledger-client-hook`이 Ed25519 세션 키로 각 도구 호출에 서명(`ala3.<payload>.<signature>`)하고 `ledger-mcp-server`가 `session_public_key`로 검증했습니다. `4.0.0`에서는 `ledger-client-hook`이 `_hostAttestation`에 `<vendor>:<session_id>`를 직접 각인하며(에이전트가 넣은 `_hostAttestation`은 `RESERVED_FIELD`로 거부), `ledger-mcp-server`는 `<vendor>:<session_id>` 형식을 검사하고 `session_grant`를 바로 확인합니다. 이전 서명 토큰이 전송되지 않도록 `ledger-mcp-server.jar`와 함께 `ledger-client-hook.jar`도 반드시 함께 교체해야 합니다.
- **단일 MCP 경계 토큰 (`ledger.mcp.token` 전용)**: `3.0.0`에서는 `ledger.mcp.auth-mode` 설정에 따라 `/mcp`가 `ledger.mcp.token` 외에 세션별 `lgt_...` Bearer 토큰도 허용했습니다. `4.0.0`에서는 `/mcp`가 상수 시간 비교로 설정된 `ledger.mcp.token`만 인증하며 `ledger.mcp.auth-mode`와 `ledger.attestation.window` 설정이 제거되었습니다. 기존에 세션별 `lgt_...` 토큰을 보내던 클라이언트는 `Authorization: Bearer` 헤더를 `ledger.mcp.token`으로 변경해야 합니다.
- **세션 키·세션 토큰 CLI 명령 및 관리 웹 엔드포인트 제거**: `ledger-cli`에서 `key-register`, `key-revoke`, `token-issue`, `token-revoke`, `token-list`가 제거되었고, `ledger-client-hook`에서 `session-key`가 제거되었으며, `ledger-admin-web`에서 `/grants/preview`, `/grants/token`, `/grants/token/revoke`, `/grants/key/revoke`, `/approval/intent`가 제거되었습니다. 권한 부여는 `POST /grants/author`, `POST /grants/sync`, 또는 `ledger-cli grant`를 사용합니다.

### 이전 절차

1. `./gradlew assemble`(시험 데이터베이스 불필요)로 `4.0.0` JAR를 빌드하거나 릴리스 JAR(`ledger-cli.jar`, `ledger-mcp-server.jar`, `ledger-admin-web.jar`, `ledger-client-hook.jar`, `ledger-hook-client.jar`)를 준비합니다.
2. 롤백 시 파일 복사와 서비스 재시작만으로 복구할 수 있도록 `/opt/agent-ledger-mcp/` 아래 현재 설치된 `3.0.0` JAR를 먼저 백업합니다.
3. `/etc/agent-ledger-mcp/` 설정 파일에 더 이상 쓰지 않는 `ledger.mcp.auth-mode` 또는 `ledger.attestation.window` 항목이 있으면 제거하고, MCP 클라이언트가 `Authorization: Bearer` 헤더에 `ledger.mcp.token`을 보내도록 확인합니다.
4. 기존 옵션 그대로 `4.0.0` JAR 디렉터리를 지정해 `deploy/install.sh`(Linux) 또는 `deploy\install.cmd`(Windows)를 다시 실행합니다. 스키마는 `V11` 그대로이므로 추가 데이터베이스 마이그레이션은 실행되지 않습니다.
5. 모든 클라이언트 훅 설치(Claude Code, Codex, Antigravity)의 `ledger-client-hook.jar`와 `ledger-hook-client.jar`를 교체하고, 실행 중인 상주 훅 프로세스를 종료해 새 `4.0.0` 훅 JAR가 깨끗하게 기동되도록 합니다.
6. 두 `/healthz` 엔드포인트(`127.0.0.1:8765/healthz`, `127.0.0.1:8865/healthz`)가 `UP`을 반환하는지 확인한 뒤, 권한이 부여된 세션이 키 등록이나 세션 토큰 발급 없이 `ledger_whoami`와 쓰기 호출에 성공하는지 확인합니다.
7. 되돌리려면 백업해 둔 `3.0.0` 서버 및 클라이언트 훅 JAR를 복원하고 제거한 `3.0.0` 설정 속성을 되돌린 뒤 `agent-ledger-mcp`와 `agent-ledger-mcp-admin` 서비스를 재시작합니다.

### 추가

- **직접 `<vendor>:<session_id>` 작성자 검증기 (`AuthorAttestationVerifier`)**: Ed25519 키 조회나 시각 창 검사 없이 호스트가 각인한 `<vendor>:<session_id>` 값을 `ActorId` 규칙(`HOST_ATTESTATION_REQUIRED`, `AUTHOR_ID_FORMAT`)으로 직접 검증합니다.
- **`ledger-admin-web`의 1-클릭 세션 권한 부여 흐름**: 소유자가 로그인한 뒤 세션 ID만으로 프로젝트 권한을 바로 부여·수정·회수(`POST /grants/author`, `POST /grants/sync`, `POST /grants/revoke`)할 수 있습니다.
- **POSIX `umask 077` 회귀 시험 (`DeployFilesUmaskTest`)**: `umask 077` 하위 JVM 프로세스를 실행해 `DeployFiles.replace`가 복사한 JAR와 렌더링한 설정 파일에 정확한 `rw-r--r--`(`0644`) 권한을 적용함을 검증합니다.
- **상주 훅 동시성 회귀 시험 (`OwnerOnlyFilesTest`, `AddressFileTest`)**: Windows 및 POSIX 호스트에서 동시 디렉터리 생성과 동시 폴링 읽기·원자적 교체 동작을 검증합니다.

### 변경

- **`ledger-admin-web` 로그인 후 소유자 변경 즉시 적용**: 패스키(`PASSKEY`), OpenID Connect(`OIDC`), 관리자 토큰(`TOKEN`)으로 한 번 로그인하면 이후 변경 작업은 CSRF 토큰과 `SameSite=Strict` 세션 쿠키 보호 아래에서 버튼마다 WebAuthn 패스키를 다시 묻지 않고 즉시 저장됩니다. 패스키와 `passkey-code`는 콘솔 로그인 수단으로 계속 지원됩니다.
- **`ledger-client-hook` 각인 단순화**: `PreToolUse` 훅이 로컬 Ed25519 키 파일을 생성하거나 읽지 않고 `_hostAttestation`에 `<vendor>:<session_id>`를 직접 각인하며, 에이전트가 임의로 넣은 `_hostAttestation` 거부(`RESERVED_FIELD`)는 그대로 유지합니다.
- **`DeployFiles.replace`의 `0644` 권한 명시 적용**: `prepare-host`와 `render-deploy`의 원자적 이름 바꾸기 직전에 `FileModes.apply`로 `FileModes.WORLD_READABLE`(`rw-r--r--`)를 명시 적용해 `umask 077`에서도 `agent-ledger-mcp` 서비스 계정이 JAR와 설정 파일을 항상 읽을 수 있도록 수정했습니다.
- **상주 훅 기동 경합 수정 (`OwnerOnlyFiles.createDirectories`, `AddressFile.write`)**: 단일 `BasicFileAttributes` 검사로 동시 최초 호출 시 불필요한 `FileAlreadyExistsException`을 방지하고, 클라이언트가 주소 파일을 폴링하는 동안 발생하는 일시적 `AccessDeniedException`에 대해 `StandardCopyOption.ATOMIC_MOVE`와 `StandardCopyOption.REPLACE_EXISTING` 및 제한 횟수 재시도를 적용했습니다.
- **버전 정렬**: Gradle 빌드, MCP 서버 메타데이터, 클라이언트 플러그인 매니페스트 버전을 `4.0.0`으로 정렬했습니다.

### 제거

- **작업별 패스키 재승인**: `ApprovalInterceptor`, `ApprovalController`, `ApprovalService`, `ApprovalIntents`, `/approval/intent`, 클라이언트 측 `data-approve` 승인 프롬프트를 제거했습니다. 로그인 1회 인증과 Spring Security CSRF 보호 및 `owner_audit` 기록으로 대체됩니다.
- **세션별 Bearer 토큰 인증**: `SessionTokenProvider`, `SessionTokenService`, `/grants/token`, `/grants/token/revoke`, `ledger-cli` 명령 `token-issue`, `token-revoke`, `token-list`를 제거했습니다. 단일 상수 시간 MCP 경계 토큰 `ledger.mcp.token`으로 대체됩니다.
- **세션별 Ed25519 키 등록 절차**: `SignedAttestationVerifier`, `AttestationProperties`, `AuthMode`, `SessionKeyService`, `ledger-client-hook` 키 저장소(`session-key`), `/grants/preview`, `/grants/key/revoke`, `ledger-cli` 명령 `key-register`, `key-revoke`를 제거했습니다. `AuthorAttestationVerifier`와 직접 `session_grant` 인가로 대체됩니다.

### 보안

- **인터넷 노출 MCP 경계 강화**: `/mcp`는 이제 설정된 상수 시간 `ledger.mcp.token`(`AgentTokenProvider`)만 허용하므로 오래된 데이터베이스 세션 토큰이 MCP 엔드포인트에 접근할 수 없습니다. `StrictHttpFirewall` 호스트 허용 목록(`403`), `TransportOriginAuthorization` Origin 허용 목록(`403`), `RequestSizeFilter`(`413`), 루프백 바인딩(`127.0.0.1`), 무상태 세션, `session_grant` 범위 검사, `Channel.REVIEWER` 분리(`VERIFY_NEEDS_REVIEWER_LOGIN`), 훅의 `RESERVED_FIELD` 위조 방지는 모두 유지됩니다.
- **관리 콘솔 경계 유지**: `ledger-admin-web`은 1회 소유자 인증(`PASSKEY` / `OIDC` / `TOKEN`), 무차별 대입 지연(`LoginAttempts` / `LoginDelay` / `PasskeyLoginGuard`), 모든 상태 변경 POST에 대한 Spring Security CSRF 토큰 검증, `SameSite=Strict` + `HttpOnly` + `Secure` 쿠키와 `sessionFixation().changeSessionId()`, 호스트 허용 목록(`403`), 엄격한 CSP(`script-src 'self'`, `frame-ancestors 'none'`, `form-action 'self'`), `owner_audit` 기록을 유지합니다.
- **신뢰 경계 변경**: 세션별 Ed25519 서명이 제거되었으므로 공유 `ledger.mcp.token`을 보유하고 권한이 부여된 `<vendor>:<session_id>`를 아는 호출자는 해당 세션 식별자를 `_hostAttestation`으로 전송할 수 있습니다. `ledger.mcp.token`을 소유자 본인 클라이언트 호스트에만 제한된 고신뢰 비밀로 취급하고, 에이전트가 로컬에서 `_hostAttestation`을 위조하지 못하도록 클라이언트 훅을 항상 활성화해 두어야 합니다.
- **배포 파일 권한**: `DeployFiles.replace`는 `FileModes.apply`를 통해 `LinkOption.NOFOLLOW_LINKS`를 계속 강제하며, 비밀 디렉터리·첨부 키·첨부 저장소는 소유자 전용 권한을 유지합니다.

### 요구 사항

- 서버 호스트 및 클라이언트 훅 호스트의 Java 25 런타임(`JDK 25`).
- PostgreSQL 데이터베이스(스키마 `V11`) 및 등록된 JDBC 드라이버. 기존 `3.0.0` 데이터베이스는 추가 스키마 마이그레이션이 필요하지 않습니다.

### 알려진 제한

- 스키마 `V11`의 기존 `session_public_key` 및 `session_token` 테이블은 스키마 체크섬과 `3.0.0` 롤백 호환성을 유지하기 위해 미사용 상태로 남아 있습니다.
- `DeployFilesUmaskTest`의 `umask 077` 하위 프로세스 시험은 POSIX 파일 시스템(Linux CI)에서 실행되며, Windows 호스트는 POSIX `umask` 대신 디렉터리 ACL로 접근 제어를 적용합니다.
