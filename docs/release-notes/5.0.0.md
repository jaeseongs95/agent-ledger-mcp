# veridger 5.0.0

## English

### Summary

`5.0.0` adds project version management, reduces repeated MCP calls and response size, and improves the console layout for large records. It is a major release because existing issue queries return an additional result key. The database schema moves from `V14` to `V15`.

### Breaking changes

- Issue details from `ledger_issue` and rows from `ledger_issues` now include `project_versions`, an array of linked version names. Clients that validate against a closed previous schema must accept this key. Update clients before switching the server if they reject unknown keys.
- Both services require `Schema-Version: V15` at startup. Apply the database migration before starting them.

### Migration

1. Download the `5.0.0` release assets and verify them against `SHA256SUMS`.
2. Stop both services. Back up the database, installed JARs, configuration and `.installed-version`. Verify that the database backup can be restored.
3. Using the new CLI and the installation's existing JDBC configuration, run `java -Duser.timezone=UTC -jar ledger-cli.jar migrate --owner-account=<owner> --app-account=<app>` with the database owner and application role names. Confirm that `V15__project_versions.sql` was applied and the application grants were refreshed.
4. Install the verified server JARs, update the installed version marker to `5.0.0`, and start both services. Check that `/healthz` reports `UP` for each service and that project versions can be read in the console.
5. To return to `4.4.1`, stop both services and restore the matching database backup, JARs, configuration and installed version marker. Start the services and recheck `/healthz`. A database restore discards changes made after the backup.

### New

- Administrators can register and rename versions per project and associate them with issues. An agent with the project's `issue` grant can register, edit, link and unlink versions through `ledger_batch` with `op=project_version`. Use `ledger_projects` with `include_versions=true` to list registered versions and `ledger_issues` with `project_version` to filter linked issues.
- All MCP tools accept `fields` for response field selection and `structured_only=true` to avoid duplicating a successful response's JSON in text. Use `ledger_get` with `include_details=true` to fetch several kinds of record details in one request. `ledger_batch` accepts `default_reason` to share a reason across operations.

### Changed

- MCP descriptions explain when to use batch calls, individual reads and independent verification. `ledger_attention` can include record context, and `ledger_whoami` can filter grants by project.
- The MCP transport reclaims idle sessions when capacity is reached while preserving sessions that are serving requests.
- Admin tables and filters handle long identifiers, long text and dense histories, release gates, milestones and session grants more consistently.

### Removed

No tools or settings were removed in this release.

### Security

- Gradle verifies resolved dependency files against checked-in SHA-256 digests.
- Project version changes use the existing project grant, session proof and write receipt rules. The console requires an authenticated owner session for the same changes.

### Requirements

- `JDK 25` for the server and client hook runtimes.
- Database on `Schema-Version: V15`.

### Known limitations

- The previous release's `/updates` page cannot apply a schema-changing release. Use the migration procedure above.
- `ledger_get` with `include_details=true` accepts at most ten IDs per call. The metadata-only limit remains unchanged.

## 한국어

### 요약

`5.0.0`은 프로젝트 버전 관리를 추가하고, 반복되는 MCP 호출과 응답 크기를 줄이며, 기록이 많은 관리 콘솔의 배치를 개선합니다. 기존 이슈 조회 결과에 키가 추가되어 주 버전을 올렸습니다. 데이터베이스 스키마는 `V14`에서 `V15`로 바뀝니다.

### 호환되지 않는 변경

- `ledger_issue` 이슈 상세와 `ledger_issues` 목록 행에 연결된 버전명 배열인 `project_versions`가 추가됩니다. 이전의 폐쇄형 스키마로 검증하는 클라이언트는 이 키를 허용해야 합니다. 알 수 없는 키를 거절하는 클라이언트는 서버 교체 전에 갱신합니다.
- 두 서비스의 기동에 `Schema-Version: V15`가 필요합니다. 서비스를 시작하기 전에 데이터베이스 마이그레이션을 적용합니다.

### 이전 절차

1. `5.0.0` 릴리스 파일을 내려받아 `SHA256SUMS`로 검증합니다.
2. 두 서비스를 중지합니다. 데이터베이스, 설치된 JAR, 설정 및 `.installed-version`을 백업합니다. 데이터베이스 백업을 복원할 수 있는지 확인합니다.
3. 새 CLI에 기존 설치의 JDBC 설정을 적용하고, DB 소유자와 애플리케이션 역할 이름을 넣어 `java -Duser.timezone=UTC -jar ledger-cli.jar migrate --owner-account=<owner> --app-account=<app>`을 실행합니다. `V15__project_versions.sql` 적용과 애플리케이션 권한 갱신을 확인합니다.
4. 검증한 서버 JAR를 설치하고 설치 버전 표시를 `5.0.0`으로 갱신한 뒤 두 서비스를 시작합니다. 각 서비스의 `/healthz`가 `UP`이고 콘솔에서 프로젝트 버전을 조회할 수 있는지 확인합니다.
5. `4.4.1`로 되돌리려면 두 서비스를 중지하고 해당 버전의 데이터베이스 백업, JAR, 설정과 설치 버전 표시를 복원합니다. 서비스를 시작한 뒤 `/healthz`를 다시 확인합니다. 데이터베이스를 복원하면 백업 이후의 변경은 사라집니다.

### 추가

- 관리자는 프로젝트별 버전을 등록하거나 이름을 바꾸고 이슈를 연결할 수 있습니다. 프로젝트의 `issue` 권한을 받은 에이전트는 `ledger_batch`에서 `op=project_version`으로 등록, 수정, 연결, 해제를 할 수 있습니다. `ledger_projects`에 `include_versions=true`를 지정해 등록된 버전을 조회하고, `ledger_issues`에 `project_version`을 지정해 연결된 이슈를 찾을 수 있습니다.
- 모든 MCP 도구에 응답 필드를 고르는 `fields`와 성공 응답의 JSON을 텍스트에 중복하지 않는 `structured_only=true`가 추가됩니다. `ledger_get`에 `include_details=true`를 지정하면 여러 종류의 기록 상세를 한 번에 가져옵니다. `ledger_batch`는 `default_reason`으로 여러 작업의 사유를 공유합니다.

### 변경

- MCP 도구 설명에 일괄 호출, 개별 조회, 독립 검증의 사용 시점을 명시했습니다. `ledger_attention`은 기록 맥락을 포함할 수 있고, `ledger_whoami`는 권한을 프로젝트로 거를 수 있습니다.
- MCP 세션이 용량 한도에 도달하면 요청을 처리 중인 세션을 유지하면서 유휴 세션을 회수합니다.
- 관리 콘솔의 표와 필터에서 긴 식별자와 본문, 이력·출시 기준·마일스톤·세션 권한이 많은 화면의 배치를 개선했습니다.

### 제거

이번 릴리스에서 제거한 도구나 설정은 없습니다.

### 보안

- Gradle은 저장소에 기록된 SHA-256 해시로 내려받은 의존성 파일을 검증합니다.
- 프로젝트 버전 변경에는 기존 프로젝트 권한, 세션 증명 및 쓰기 영수증 규칙을 적용합니다. 콘솔에서 같은 변경을 하려면 인증된 소유자 세션이 필요합니다.

### 요구 사항

- 서버와 클라이언트 훅 실행에 `JDK 25`가 필요합니다.
- 데이터베이스에 `Schema-Version: V15`가 필요합니다.

### 알려진 제한

- 이전 버전의 `/updates` 화면은 스키마가 바뀌는 릴리스를 적용할 수 없습니다. 위 이전 절차를 따릅니다.
- `ledger_get`에 `include_details=true`를 지정하면 호출당 ID를 최대 10개 받을 수 있습니다. 메타데이터만 조회할 때의 한도는 그대로입니다.
