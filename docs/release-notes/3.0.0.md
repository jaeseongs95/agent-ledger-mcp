# agent-ledger-mcp 3.0.0

## English

### Summary

3.0.0 renames the product, repository, Maven/Gradle group, Java root package, default OS instance name, service units, default installation paths, client hook state directories, client plugin identifiers, and host attestation protocol from `pg-ledger-mcp` (`org.pgledger`) to `agent-ledger-mcp` (`org.agentledger`). Because this overhaul changes the `_hostAttestation` token prefix and signing domain, default service and configuration paths, client hook directories, plugin names, and Java package coordinates, the major version increases from `2.1.1` to `3.0.0`.

### Breaking changes

1. **Product name, Gradle group, and Java root package renamed.** The root project name in `settings.gradle.kts`, Maven/Gradle group in `build.gradle.kts`, and Java root package changed from `pg-ledger-mcp` / `org.pgledger` to `agent-ledger-mcp` / `org.agentledger`. Any code, logging property (`LOGGING_LEVEL_ORG_PGLEDGER_HOOK` to `LOGGING_LEVEL_ORG_AGENTLEDGER_HOOK`), or custom integration referencing `org.pgledger` must update to `org.agentledger`.
2. **Default instance name, OS service units, and installation paths changed.** The default value of `ledger.secrets.instance` changed from `pg-ledger-mcp` to `agent-ledger-mcp`. Default Linux services changed from `pg-ledger-mcp.service` and `pg-ledger-mcp-admin.service` to `agent-ledger-mcp.service` and `agent-ledger-mcp-admin.service`; default Linux directories changed from `/etc/pg-ledger-mcp`, `/opt/pg-ledger-mcp`, and `/var/lib/pg-ledger-mcp` to `/etc/agent-ledger-mcp`, `/opt/agent-ledger-mcp`, and `/var/lib/agent-ledger-mcp` (and on Windows from `C:/ProgramData/pg-ledger-mcp` to `C:/ProgramData/agent-ledger-mcp`). Default `ledger.secrets.home`, `ledger.admin.driver-file`, and `ledger.admin.driver-directory` follow the new instance name. Existing operators migrating in place must move or copy `secrets/`, `attachment-keys/`, `local.yaml`, and `attachments/` to the new paths or explicitly pass the previous instance name.
3. **Host attestation protocol upgraded from `pgla2` to `ala3`.** The `_hostAttestation` signing domain changed from `pg-ledger-mcp/attestation/v2` to `agent-ledger-mcp/attestation/v3` and the token prefix changed from `pgla2` to `ala3`. Tokens produced by `2.1.1` client hooks (`pgla2`) are rejected with `ATTESTATION_MALFORMED`. Every client host using `_hostAttestation` must update `ledger-client-hook.jar` and `ledger-hook-resident.jar` to `3.0.0`. Callers authenticating with per-author HTTP Bearer session tokens (`lgt_...`) in `STANDARD` mode are unaffected.
4. **Client hook directories and plugin identifiers renamed.** The default hook key and resident state folder changed from `~/.pg-ledger-mcp` to `~/.agent-ledger-mcp`. The Antigravity and Codex plugin identifier changed from `pg-ledger-host-attestation` to `agent-ledger-host-attestation`, and the Claude plugin name changed from `pg-ledger-mcp` to `agent-ledger-mcp`. Existing hook hosts must copy or move their session keys from `~/.pg-ledger-mcp` to `~/.agent-ledger-mcp` (or re-register keys) and reinstall the `3.0.0` plugins.
5. **Default source repository URL and Admin Web theme storage key changed.** The default `ledger.source.url` changed from `https://github.com/jaeseongs95/pg-ledger-mcp` to `https://github.com/jaeseongs95/agent-ledger-mcp`. The browser theme preference key changed from `pgledger.theme` to `agentledger.theme`; existing browser sessions revert to the system default theme until toggled once.

### Migration

1. Build the `3.0.0` jars (`ledger-cli.jar`, `ledger-mcp-server.jar`, `ledger-admin-web.jar`, `ledger-migrate-1x.jar`, `ledger-client-hook.jar`, and `ledger-hook-resident.jar`) with `./gradlew assemble`.
2. Back up the PostgreSQL database with your DBMS dump tool and archive `/etc/pg-ledger-mcp`, `/opt/pg-ledger-mcp`, and `/var/lib/pg-ledger-mcp` (or `C:/ProgramData/pg-ledger-mcp` on Windows) so rollback can restore the `2.1.1` installation intact.
3. Stop and disable the `2.1.1` services (`pg-ledger-mcp.service` and `pg-ledger-mcp-admin.service` on Linux) before installing `3.0.0` under the new default name `agent-ledger-mcp` on the same ports.
4. Run `deploy/install.sh` (Linux) or `deploy\install.cmd` (Windows) with the `3.0.0` jars directory and existing database and host options to create the `agent-ledger-mcp` service account, `/etc/agent-ledger-mcp`, `/opt/agent-ledger-mcp`, `/var/lib/agent-ledger-mcp`, and the `agent-ledger-mcp.service` and `agent-ledger-mcp-admin.service` units.
5. Copy `secrets/`, `attachment-keys/`, `local.yaml` (updating any hardcoded `/etc/pg-ledger-mcp` or `/var/lib/pg-ledger-mcp` paths), and `attachments/` from the `2.1.1` backup into the corresponding `agent-ledger-mcp` directories with owner-only permissions owned by the `agent-ledger-mcp` service user, then restart `agent-ledger-mcp.service` and `agent-ledger-mcp-admin.service`. The database schema remains at `V11`, so existing issues, specifications, tasks, criteria, grants, passkeys, and session keys stay intact.
6. Verify `127.0.0.1:8765/healthz` and `127.0.0.1:8865/healthz` return `UP`, and run `ledger-cli attachments-check` to confirm zero missing or damaged attachments.
7. Update every client host: copy session keys from `~/.pg-ledger-mcp` to `~/.agent-ledger-mcp` and install the `3.0.0` plugin manifests and `ledger-client-hook.jar` / `ledger-hook-resident.jar`.
8. To roll back, stop and disable `agent-ledger-mcp.service` and `agent-ledger-mcp-admin.service`, restore the `2.1.1` backups if modified, and re-enable and start `pg-ledger-mcp.service` and `pg-ledger-mcp-admin.service` (restoring `2.1.1` client hooks on client hosts).

### New

No new MCP tools, Admin Web pages, CLI commands, or database tables were added in this release.

### Changed

- Aligned all 14 Gradle modules, Spring configuration metadata, installer headers, client plugin manifests, documentation, and automated architecture and documentation tests to `agent-ledger-mcp`, `org.agentledger`, and version `3.0.0`.
- Preserved historical `2.x` release notes and legacy 1.x migration inputs in `ledger-migrate-1x` (`stop-1x` default name `pg-ledger-mcp` and `/etc/pg-ledger-mcp/env`) unchanged.

### Removed

- Support for the `pgla2` (`pg-ledger-mcp/attestation/v2`) host attestation format was removed and replaced by `ala3` (`agent-ledger-mcp/attestation/v3`).
- The legacy `org.pgledger` package namespace and `pg-ledger-host-attestation` plugin identifier were removed and replaced by `org.agentledger` and `agent-ledger-host-attestation`.

### Security

- Domain separation of `_hostAttestation` signatures is updated to `agent-ledger-mcp/attestation/v3` with prefix `ala3`, preventing cross-version token replay between `2.1.1` (`pgla2`) and `3.0.0` (`ala3`).
- Owner-only directory permissions for `/etc/agent-ledger-mcp`, `/var/lib/agent-ledger-mcp`, and `~/.agent-ledger-mcp` enforce the same personal-edition trust boundary as `2.1.1`.

### Requirements

- Java 25 runtime (`JDK 25`) on both the server host and client hook hosts.
- Existing PostgreSQL database (schema `V1` through `V11`) and registered JDBC driver.

### Known limitations

- In-place migration from a `2.1.1` `pg-ledger-mcp` instance to a `3.0.0` `agent-ledger-mcp` instance requires moving or copying `secrets/`, `attachment-keys/`, `local.yaml`, and `attachments/` manually as described in Migration; no automated `2.x`-to-`3.0` migration tool is bundled.

## 한국어

### 요약

3.0.0은 제품명, 저장소, Maven/Gradle 그룹, Java 루트 패키지, 기본 OS 인스턴스 이름, 서비스 유닛, 기본 설치 경로, 클라이언트 훅 상태 디렉터리, 클라이언트 플러그인 식별자, 호스트 증명 프로토콜을 `pg-ledger-mcp`(`org.pgledger`)에서 `agent-ledger-mcp`(`org.agentledger`)로 전면 개명한 메이저 릴리스입니다. 이 개명으로 `_hostAttestation` 토큰 접두사와 서명 도메인, 기본 서비스·설정 경로, 클라이언트 훅 디렉터리, 플러그인 이름, Java 패키지 좌표가 바뀌므로 주 버전을 `2.1.1`에서 `3.0.0`으로 올렸습니다.

### 호환되지 않는 변경

1. **제품명, Gradle 그룹, Java 루트 패키지 개명.** `settings.gradle.kts`의 루트 프로젝트 이름, `build.gradle.kts`의 Maven/Gradle 그룹, Java 루트 패키지가 `pg-ledger-mcp` / `org.pgledger`에서 `agent-ledger-mcp` / `org.agentledger`로 바뀌었습니다. `org.pgledger`를 참조하는 코드, 로깅 속성(`LOGGING_LEVEL_ORG_PGLEDGER_HOOK`에서 `LOGGING_LEVEL_ORG_AGENTLEDGER_HOOK`으로 변경) 또는 사용자 정의 연동은 `org.agentledger`로 갱신해야 합니다.
2. **기본 인스턴스 이름, OS 서비스 유닛, 설치 경로 변경.** `ledger.secrets.instance`의 기본값이 `pg-ledger-mcp`에서 `agent-ledger-mcp`로 바뀌었습니다. Linux 기본 서비스는 `pg-ledger-mcp.service`, `pg-ledger-mcp-admin.service`에서 `agent-ledger-mcp.service`, `agent-ledger-mcp-admin.service`로, Linux 기본 디렉터리는 `/etc/pg-ledger-mcp`, `/opt/pg-ledger-mcp`, `/var/lib/pg-ledger-mcp`에서 `/etc/agent-ledger-mcp`, `/opt/agent-ledger-mcp`, `/var/lib/agent-ledger-mcp`로 바뀌었습니다(Windows는 `C:/ProgramData/pg-ledger-mcp`에서 `C:/ProgramData/agent-ledger-mcp`로 변경). 기본 `ledger.secrets.home`, `ledger.admin.driver-file`, `ledger.admin.driver-directory`도 새 인스턴스 이름을 따릅니다. 기존 운영자가 제자리 이전할 때는 `secrets/`, `attachment-keys/`, `local.yaml`, `attachments/`를 새 경로로 복사·이동하거나 이전 인스턴스 이름을 명시적으로 지정해야 합니다.
3. **호스트 증명 프로토콜 `pgla2`에서 `ala3`로 상향.** `_hostAttestation` 서명 도메인이 `pg-ledger-mcp/attestation/v2`에서 `agent-ledger-mcp/attestation/v3`로, 토큰 접두사가 `pgla2`에서 `ala3`로 바뀌었습니다. `2.1.1` 클라이언트 훅이 생성한 토큰(`pgla2`)은 `ATTESTATION_MALFORMED`로 거절됩니다. `_hostAttestation`을 사용하는 모든 클라이언트 호스트는 `ledger-client-hook.jar`와 `ledger-hook-resident.jar`를 `3.0.0`으로 갱신해야 합니다. `STANDARD` 모드에서 작성자별 HTTP Bearer 세션 토큰(`lgt_...`)으로 인증하는 호출자는 영향을 받지 않습니다.
4. **클라이언트 훅 디렉터리 및 플러그인 식별자 개명.** 훅의 기본 키 및 상주 상태 폴더가 `~/.pg-ledger-mcp`에서 `~/.agent-ledger-mcp`로 바뀌었습니다. Antigravity와 Codex 플러그인 식별자가 `pg-ledger-host-attestation`에서 `agent-ledger-host-attestation`으로, Claude 플러그인 이름이 `pg-ledger-mcp`에서 `agent-ledger-mcp`로 바뀌었습니다. 기존 훅 호스트는 `~/.pg-ledger-mcp`의 세션 키를 `~/.agent-ledger-mcp`로 복사·이동하거나 키를 다시 등록하고 `3.0.0` 플러그인을 재설치해야 합니다.
5. **기본 소스 저장소 URL 및 관리 웹 테마 저장 키 변경.** 기본 `ledger.source.url`이 `https://github.com/jaeseongs95/pg-ledger-mcp`에서 `https://github.com/jaeseongs95/agent-ledger-mcp`로 바뀌었습니다. 브라우저 테마 저장 키가 `pgledger.theme`에서 `agentledger.theme`으로 바뀌어 기존 브라우저 세션은 테마를 한 번 다시 전환할 때까지 시스템 기본 테마를 따릅니다.

### 이전 절차

1. `./gradlew assemble`로 `3.0.0` JAR(`ledger-cli.jar`, `ledger-mcp-server.jar`, `ledger-admin-web.jar`, `ledger-migrate-1x.jar`, `ledger-client-hook.jar`, `ledger-hook-resident.jar`)를 빌드합니다.
2. 롤백 시 `2.1.1` 설치를 원형대로 복구할 수 있도록 DBMS 덤프 도구로 PostgreSQL 데이터베이스를 백업하고 `/etc/pg-ledger-mcp`, `/opt/pg-ledger-mcp`, `/var/lib/pg-ledger-mcp`(Windows는 `C:/ProgramData/pg-ledger-mcp`)를 아카이브 백업합니다.
3. 같은 포트에서 새 기본 이름 `agent-ledger-mcp`로 `3.0.0`을 설치하기 전에 `2.1.1` 서비스(Linux의 `pg-ledger-mcp.service`, `pg-ledger-mcp-admin.service`)를 중지하고 비활성화합니다.
4. `3.0.0` JAR 디렉터리와 기존 데이터베이스·호스트 옵션으로 `deploy/install.sh`(Linux) 또는 `deploy\install.cmd`(Windows)를 실행해 `agent-ledger-mcp` 서비스 계정, `/etc/agent-ledger-mcp`, `/opt/agent-ledger-mcp`, `/var/lib/agent-ledger-mcp`, 그리고 `agent-ledger-mcp.service` 및 `agent-ledger-mcp-admin.service` 유닛을 생성합니다.
5. `2.1.1` 백업에서 `secrets/`, `attachment-keys/`, `local.yaml`(하드코딩된 `/etc/pg-ledger-mcp` 또는 `/var/lib/pg-ledger-mcp` 경로가 있으면 갱신), `attachments/`를 해당 `agent-ledger-mcp` 디렉터리로 복사하고 `agent-ledger-mcp` 서비스 사용자 소유 및 소유자 전용 권한으로 맞춘 뒤 `agent-ledger-mcp.service`와 `agent-ledger-mcp-admin.service`를 재시작합니다. 데이터베이스 스키마는 `V11` 그대로 유지되므로 기존 이슈, 명세, 작업, 기준, 부여, 패스키, 세션 키는 보존됩니다.
6. `127.0.0.1:8765/healthz`와 `127.0.0.1:8865/healthz`가 `UP`을 반환하는지 확인하고 `ledger-cli attachments-check`를 실행해 누락되거나 손상된 첨부가 없는지 검증합니다.
7. 모든 클라이언트 호스트에서 `~/.pg-ledger-mcp`의 세션 키를 `~/.agent-ledger-mcp`로 복사하고 `3.0.0` 플러그인 매니페스트와 `ledger-client-hook.jar` / `ledger-hook-resident.jar`를 설치합니다.
8. 되돌리려면 `agent-ledger-mcp.service`와 `agent-ledger-mcp-admin.service`를 중지·비활성화하고, 변경된 파일이 있으면 `2.1.1` 백업을 복원한 뒤 `pg-ledger-mcp.service`와 `pg-ledger-mcp-admin.service`를 다시 활성화·시작합니다(클라이언트 호스트도 `2.1.1` 훅으로 복원).

### 추가

이 릴리스에서 새로 추가된 MCP 도구, 관리 웹 화면, CLI 명령 또는 데이터베이스 표는 없습니다.

### 변경

- 14개 Gradle 모듈 전체, Spring 설정 메타데이터, 설치기 헤더, 클라이언트 플러그인 매니페스트, 문서, 아키텍처·문서 자동 시험을 `agent-ledger-mcp`, `org.agentledger`, 버전 `3.0.0`에 맞게 정렬했습니다.
- 과거 `2.x` 릴리스 노트 이력과 `ledger-migrate-1x`의 1.x 이전 입력(`stop-1x` 기본 이름 `pg-ledger-mcp`, `/etc/pg-ledger-mcp/env`)은 기존 그대로 보존했습니다.

### 제거

- `pgla2`(`pg-ledger-mcp/attestation/v2`) 호스트 증명 형식 지원을 제거하고 `ala3`(`agent-ledger-mcp/attestation/v3`)로 대체했습니다.
- 기존 `org.pgledger` 패키지 네임스페이스와 `pg-ledger-host-attestation` 플러그인 식별자를 제거하고 `org.agentledger`와 `agent-ledger-host-attestation`으로 대체했습니다.

### 보안

- `_hostAttestation` 서명의 도메인 분리를 `agent-ledger-mcp/attestation/v3`와 접두사 `ala3`로 갱신해 `2.1.1`(`pgla2`)과 `3.0.0`(`ala3`) 간 교차 버전 토큰 재사용을 방지합니다.
- `/etc/agent-ledger-mcp`, `/var/lib/agent-ledger-mcp`, `~/.agent-ledger-mcp`의 소유자 전용 디렉터리 권한은 `2.1.1`과 동일한 개인판 신뢰 경계를 유지합니다.

### 요구 사항

- 서버 호스트 및 클라이언트 훅 호스트의 Java 25 런타임(`JDK 25`).
- 기존 PostgreSQL 데이터베이스(스키마 `V1`~`V11`) 및 등록된 JDBC 드라이버.

### 알려진 제한

- `2.1.1`의 `pg-ledger-mcp` 인스턴스에서 `3.0.0`의 `agent-ledger-mcp` 인스턴스로 제자리 이전할 때는 이전 절차에 따라 `secrets/`, `attachment-keys/`, `local.yaml`, `attachments/`를 수동 복사·이동해야 하며, 별도의 `2.x`→`3.0` 자동 이전 도구는 포함되지 않습니다.
