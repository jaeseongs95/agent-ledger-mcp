# veridger 4.0.1

## English

### Summary

`4.0.1` is a patch release for the client hook (`ledger-client-hook.jar` and `ledger-hook-resident.jar`) that fixes gateway upstream prefix matching across `CodexDialect`, `ClaudeDialect`, and `AntigravityDialect`. In `4.0.0`, registering an MCP server under the new product name `veridger` while connecting through a gateway whose upstream prefix is `ledger` produced tool names such as `mcp__veridger__ledger_ledger_whoami` and `mcp__veridger__ledger_artifact_begin`, which the hook skipped and caused `HOST_ATTESTATION_REQUIRED`. Because every server contract, database schema (`V11`), CLI command, and admin endpoint remains backward-compatible with `4.0.0`, the patch version increases from `4.0.0` to `4.0.1`.

### Breaking changes

There are no breaking changes in this release. Existing `4.0.0` MCP servers, admin web installations, database schemas (`V11`), configuration files, and client hook manifests continue to work without modification.

### Migration

1. Build the `4.0.1` jars with `./gradlew assemble` (no test database required) or download `ledger-client-hook.jar` and `ledger-hook-resident.jar` from the `4.0.1` release.
2. Back up the installed `4.0.0` client hook jars and stop any running resident process with `java -jar ledger-client-hook.jar stop`.
3. Replace `ledger-client-hook.jar` and `ledger-hook-resident.jar` in your Codex, Claude Code, and Antigravity hook installations. No server restart or database migration is required because the server and schema (`V11`) are unchanged from `4.0.0`.
4. If the Codex hook command path changed, review and trust the updated hook in `/hooks`, then verify that `mcp__veridger__ledger_ledger_whoami` stamps `_hostAttestation` and succeeds.
5. To roll back, restore the backed-up `4.0.0` `ledger-client-hook.jar` and `ledger-hook-resident.jar` and stop the resident process with `java -jar ledger-client-hook.jar stop`.

### New

- **Canonical gateway prefix helper (`McpToolName`)**: Added `McpToolName.GATEWAY_PREFIXES` (`ledger` and `veridger`) so all three host dialects recognise canonical Veridger gateway upstream prefixes even when the client MCP server alias differs from the upstream name.
- **Gateway alias-mismatch regression coverage**: Expanded `SigningTest`, `ToolSelectionTest`, and `ManifestTest` to cover mismatched client server aliases and canonical gateway prefixes across Codex, Claude Code, and Antigravity (both direct and `call_mcp_tool` invocations).

### Changed

- **Unified gateway prefix matching across all three dialects**: Updated `CodexDialect`, `ClaudeDialect`, and `AntigravityDialect` so gateway-prefixed write and attachment calls are stamped when the upstream prefix equals the client server name, `ledger`, or `veridger`.
- **Client documentation and release version alignment**: Updated the Codex, Claude Code, and Antigravity plugin READMEs to document the canonical `ledger` and `veridger` gateway prefixes, and aligned the Gradle build, MCP server metadata, and client plugin manifests to `4.0.1`.

### Removed

No features, endpoints, CLI commands, MCP tools, or settings were removed in this release.

### Security

- Unrelated gateway upstream prefixes (such as `other_` or `sennard_`) remain untouched so `_hostAttestation` is never injected into other MCP upstreams behind a shared gateway.
- Local anti-spoofing (`RESERVED_FIELD`) continues to deny any agent-supplied `_hostAttestation` on all direct and gateway-prefixed write and attachment calls.

### Requirements

- Java 25 runtime (`JDK 25`) on the server host and client hook hosts.
- Existing `4.0.0` server installation and PostgreSQL schema (`V11`); no server upgrade is required to adopt the `4.0.1` client hook.

### Known limitations

- Gateways that prefix Veridger tools with a custom upstream name other than the client server alias, `ledger`, or `veridger` still require matching the client MCP server alias to the upstream name.

## 한국어

### 요약

`4.0.1`은 `CodexDialect`, `ClaudeDialect`, `AntigravityDialect` 전체에서 게이트웨이 업스트림 접두어 매칭을 수정한 클라이언트 훅(`ledger-client-hook.jar`, `ledger-hook-resident.jar`) 패치 릴리스입니다. `4.0.0`에서는 클라이언트 MCP 서버를 새 제품명 `veridger`로 등록하고 업스트림 접두어가 `ledger`인 게이트웨이에 연결하면 `mcp__veridger__ledger_ledger_whoami`, `mcp__veridger__ledger_artifact_begin` 같은 도구 이름을 훅이 건너뛰어 `HOST_ATTESTATION_REQUIRED` 오류가 발생했습니다. 서버 계약, 데이터베이스 스키마(`V11`), CLI 명령, 관리 웹 엔드포인트가 모두 `4.0.0`과 하위 호환되므로 패치 버전을 `4.0.0`에서 `4.0.1`로 올렸습니다.

### 호환되지 않는 변경

이 릴리스에는 호환되지 않는 변경이 없습니다. 기존 `4.0.0` MCP 서버, 관리 웹 설치, 데이터베이스 스키마(`V11`), 설정 파일, 클라이언트 훅 매니페스트는 수정 없이 그대로 동작합니다.

### 이전 절차

1. `./gradlew assemble`(시험 데이터베이스 불필요)로 `4.0.1` JAR를 빌드하거나 `4.0.1` 릴리스에서 `ledger-client-hook.jar`와 `ledger-hook-resident.jar`를 받습니다.
2. 설치된 `4.0.0` 클라이언트 훅 JAR를 백업하고 `java -jar ledger-client-hook.jar stop`으로 실행 중인 상주 프로세스를 종료합니다.
3. Codex, Claude Code, Antigravity 훅 설치 경로의 `ledger-client-hook.jar`와 `ledger-hook-resident.jar`를 교체합니다. 서버와 스키마(`V11`)는 `4.0.0`과 동일하므로 서버 재시작이나 데이터베이스 마이그레이션은 필요하지 않습니다.
4. Codex 훅 명령 경로가 바뀌었다면 `/hooks`에서 갱신된 훅을 확인하고 신뢰한 뒤, `mcp__veridger__ledger_ledger_whoami` 호출에 `_hostAttestation`이 정상 각인되는지 확인합니다.
5. 되돌리려면 백업해 둔 `4.0.0`의 `ledger-client-hook.jar`와 `ledger-hook-resident.jar`를 복원하고 `java -jar ledger-client-hook.jar stop`으로 상주 프로세스를 종료합니다.

### 추가

- **정준 게이트웨이 접두어 도우미 (`McpToolName`)**: 클라이언트 MCP 서버 별칭과 게이트웨이 업스트림 이름이 달라도 세 호스트 Dialect가 Veridger 정준 게이트웨이 접두어를 인식하도록 `McpToolName.GATEWAY_PREFIXES`(`ledger`, `veridger`)를 추가했습니다.
- **게이트웨이 별칭 불일치 회귀 시험**: Codex, Claude Code, Antigravity(직접 호출 및 `call_mcp_tool` 호출)에서 클라이언트 서버 별칭과 정준 게이트웨이 접두어가 다른 경우를 검증하도록 `SigningTest`, `ToolSelectionTest`, `ManifestTest`를 확장했습니다.

### 변경

- **세 호스트 Dialect의 게이트웨이 접두어 매칭 통합**: 업스트림 접두어가 클라이언트 서버 이름과 같거나 `ledger` 또는 `veridger`일 때 게이트웨이 접두어가 붙은 쓰기·첨부 호출에 각인하도록 `CodexDialect`, `ClaudeDialect`, `AntigravityDialect`를 수정했습니다.
- **클라이언트 문서 및 릴리스 버전 정렬**: Codex, Claude Code, Antigravity 플러그인 README에 정준 `ledger`·`veridger` 게이트웨이 접두어 규칙을 반영하고 Gradle 빌드, MCP 서버 메타데이터, 클라이언트 플러그인 매니페스트 버전을 `4.0.1`로 정렬했습니다.

### 제거

이 릴리스에서 제거된 기능, 엔드포인트, CLI 명령, MCP 도구 또는 설정은 없습니다.

### 보안

- 무관한 게이트웨이 업스트림 접두어(`other_`, `sennard_` 등)는 계속 건드리지 않으므로 공유 게이트웨이 뒤의 다른 MCP 업스트림에 `_hostAttestation`이 주입되지 않습니다.
- 로컬 위조 방지(`RESERVED_FIELD`)는 모든 직접 호출과 게이트웨이 접두어 쓰기·첨부 호출에서 에이전트가 직접 넣은 `_hostAttestation`을 계속 거부합니다.

### 요구 사항

- 서버 호스트 및 클라이언트 훅 호스트의 Java 25 런타임(`JDK 25`).
- 기존 `4.0.0` 서버 설치 및 PostgreSQL 스키마(`V11`). `4.0.1` 클라이언트 훅 적용을 위한 서버 업그레이드는 필요하지 않습니다.

### 알려진 제한

- 게이트웨이가 클라이언트 서버 별칭, `ledger`, `veridger` 이외의 임의 업스트림 이름으로 Veridger 도구에 접두어를 붙이는 경우에는 여전히 클라이언트 MCP 서버 별칭을 업스트림 이름과 맞춰야 합니다.
