# pg-ledger-mcp 2.1.1

## English

### Summary

2.1.1 is a patch release for the Admin Web (`ledger-admin-web.jar`) that redesigns session access management around per-session cards, unifies add, edit, and revoke or deactivate actions behind button-triggered native modal dialogs across Projects, Grants, and Common Codes, and adds live search UI to all three screens. Because every MCP tool contract, database schema, security header, and existing HTTP endpoint remains backward-compatible, the patch version increases from `2.1.0` to `2.1.1`.

### Breaking changes

There are no breaking changes in this release. Existing MCP clients, client hooks, database schemas (`V1` through `V11`), configuration files, JSON API clients, and Admin Web POST endpoints continue to work without modification.

### Migration

1. Build the `2.1.1` jars with `./gradlew assemble` (no test database required) or obtain the release build.
2. Back up the currently installed jars before replacing them so rollback is a single file copy and service restart.
3. Re-run `deploy/install.sh` (Linux) or `deploy\install.cmd` (Windows) with the `2.1.1` jars directory and existing options; no new database migration runs because the schema remains at `V11`.
4. Verify both `/healthz` endpoints (`127.0.0.1:8765/healthz` and `127.0.0.1:8865/healthz`) return `UP` and sign in to the Admin Web to confirm the updated Projects, Grants, and Common Codes screens load cleanly.
5. To roll back, restore the backed-up `2.1.0` jars and restart `pg-ledger-mcp` and `pg-ledger-mcp-admin`.

### New

- **Session-centric `/grants` view and atomic operations**: Added `SessionAccessView` to group keys, bearer tokens, and project grants per author, `POST /grants/sync` (`GrantService.syncProjectScopes`) to apply scope additions and revocations for a project in a single transaction and passkey approval while preserving unchanged grant IDs, and optional one-step initial project scope issuance on `POST /grants/tokens` (`GrantService.issueTokenWithOptionalGrants`).
- **Unified native modal CRUD across `/projects`, `/grants`, and `/codes`**: Extracted every add, edit, revoke, and deactivate or reactivate action into top-level or row buttons that open standard `<dialog>` modals via `showModal()`, with focus restoration, backdrop close, Korean IME-safe `Escape` handling, and `data-open-on-load="true"` auto-reopen for HTML 4xx validation recovery and key fingerprint confirmation.
- **Per-screen search UI**: Added unified search toolbars with live match counters, filter reset controls, and IME-safe (`compositionstart` and `compositionend`) filtering on `/projects`, `/grants`, and `/codes`.
- **Automated UX regression tests**: Added `GrantsUxTest` (`GUX-01` through `GUX-05`) and `ModalCrudUxTest` (`MUX-01` through `MUX-03`) covering session-card grouping, atomic scope sync, one-step bearer token plus grant creation and rollback, zero mutating forms outside modal dialogs, search controls, and 4xx modal auto-reopen.

### Changed

- **Modal-aware passkey feedback (`passkey.js`)**: Updated status rendering so passkey prompts, errors, and cancellations display inside the active dialog (`[data-modal-status]`) while preserving `#passkey-status` outside dialogs.
- **Shared dialog and toolbar controller (`admin-ui.js`, `admin.css`)**: Consolidated modal open, prefill, close, and search/filter logic in `admin-ui.js` with responsive modal and toolbar styles in `admin.css`.
- **Common code state transitions**: Added quick deactivate and reactivate confirmation modals posting to `POST /codes` with metadata preserved, while keeping hard deletion forbidden (`DELETE /codes` and `POST /codes/delete` remain `405 COMMON_CODE_DELETE_FORBIDDEN`).
- **Translations and version alignment**: Added modal, search, counter, and deactivate/reactivate messages in `admin.properties` and `admin_ko.properties` with 100% EN/KO key parity, and aligned Gradle build, MCP server metadata, and client hook manifests to `2.1.1`.

### Removed

No features, endpoints, CLI commands, MCP tools, or settings were removed in this release.

### Security

- Strict Content Security Policy compliance is preserved across all templates with zero inline `<script>`, `<style>`, `style=`, or `on*=` handlers (`ArchitectureTest`, `SecurityHeadersTest`).
- `POST /grants/sync` and `POST /grants/tokens` enforce the same owner passkey approval and CSRF protections as all other mutating Admin Web endpoints, and `/grants/preview` fingerprint confirmation remains mandatory before registering or replacing a session key.
- Enrollment sessions holding `ROLE_ENROLL` remain restricted to passkey registration.

### Requirements

- Java 25 runtime (`JDK 25`) on the server host and client hook hosts.
- Existing `2.1.0` PostgreSQL database (schema `V11`) and registered JDBC driver; no additional runtime dependencies or external frontend build tools are introduced.

### Known limitations

- Automated regression tests cover MockMvc rendering, CSP headers, i18n parity, and HTTP/form contracts; live visual inspection across desktop and mobile browsers remains a manual check when host hooks block browser subagent MCP calls.

## 한국어

### 요약

2.1.1은 관리 웹(`ledger-admin-web.jar`)의 부여 화면을 세션 카드 중심으로 재설계하고, 프로젝트·부여·공통코드 세 메뉴의 추가·수정·회수·비활성화 작업을 모두 버튼 기반 네이티브 모달 팝업으로 통합하며, 세 화면 각각에 실시간 검색 UI를 추가한 패치 릴리스입니다. 모든 MCP 도구 계약, 데이터베이스 스키마, 보안 헤더, 기존 HTTP 엔드포인트가 하위 호환을 유지하므로 패치 버전을 `2.1.0`에서 `2.1.1`로 올렸습니다.

### 호환되지 않는 변경

이 릴리스에는 호환되지 않는 변경이 없습니다. 기존 MCP 클라이언트, 클라이언트 훅, 데이터베이스 스키마(`V1`~`V11`), 설정 파일, JSON API 클라이언트, 관리 웹 POST 엔드포인트는 수정 없이 그대로 동작합니다.

### 이전 절차

1. `./gradlew assemble`(시험 데이터베이스 불필요)로 `2.1.1` JAR를 빌드하거나 릴리스 빌드를 준비합니다.
2. 롤백 시 파일 복사와 서비스 재시작만으로 복구할 수 있도록 현재 설치된 JAR를 먼저 백업합니다.
3. 기존 옵션 그대로 `2.1.1` JAR 디렉터리를 지정해 `deploy/install.sh`(Linux) 또는 `deploy\install.cmd`(Windows)를 다시 실행합니다. 스키마는 `V11` 그대로이므로 추가 데이터베이스 마이그레이션은 실행되지 않습니다.
4. 두 `/healthz` 엔드포인트(`127.0.0.1:8765/healthz`, `127.0.0.1:8865/healthz`)가 `UP`을 반환하는지 확인하고 관리 웹에 로그인해 개편된 프로젝트, 부여, 공통코드 화면이 정상 표시되는지 확인합니다.
5. 되돌리려면 백업해 둔 `2.1.0` JAR를 복원하고 `pg-ledger-mcp`와 `pg-ledger-mcp-admin` 서비스를 재시작합니다.

### 추가

- **세션 중심 `/grants` 화면 및 원자적 연산**: 작성자별 키·베어러 토큰·프로젝트 부여를 묶어 보여 주는 `SessionAccessView`, 변경되지 않은 부여 ID를 유지하면서 한 트랜잭션과 패스키 1회 승인으로 프로젝트 권한 추가·회수를 동시에 반영하는 `POST /grants/sync`(`GrantService.syncProjectScopes`), 그리고 `POST /grants/tokens`에서 초기 프로젝트 권한을 한 번에 부여하는 선택 경로(`GrantService.issueTokenWithOptionalGrants`)를 추가했습니다.
- **`/projects`, `/grants`, `/codes` 공통 네이티브 모달 CRUD**: 세 메뉴의 모든 추가·수정·회수·비활성화/재활성화 동작을 상단 또는 행 버튼으로 분리하고 표준 `<dialog>` 모달(`showModal()`)에서 관리하도록 통합했습니다. 닫기 시 포커스 복원, 배경 클릭 닫기, 한국어 입력기(IME) 안전 `Escape` 처리, 그리고 HTML 4xx 오류 복구 및 공개키 지문 확인을 위한 `data-open-on-load="true"` 자동 재열기를 제공합니다.
- **화면별 검색 UI**: `/projects`, `/grants`, `/codes` 각각에 실시간 일치 건수 표시, 필터 초기화, 한국어 입력기 조합 안전(`compositionstart`, `compositionend`) 검색 툴바를 추가했습니다.
- **자동 UX 회귀 시험**: 세션 카드 묶음, 원자적 범위 동기화, 베어러 토큰·초기 부여 1단계 발급 및 롤백, 모달 외부 변경 폼 0건, 검색 컨트롤, 4xx 모달 자동 재열기를 검증하는 `GrantsUxTest`(`GUX-01`~`GUX-05`)와 `ModalCrudUxTest`(`MUX-01`~`MUX-03`)를 추가했습니다.

### 변경

- **모달 인식 패스키 피드백(`passkey.js`)**: 패스키 안내, 오류, 취소 메시지가 열린 대화상자 내부(`[data-modal-status]`)에 표시되도록 개선했으며, 대화상자 외부에서는 기존 `#passkey-status` 배너를 그대로 유지합니다.
- **공통 대화상자 및 툴바 제어기(`admin-ui.js`, `admin.css`)**: 모달 열기·사전 채움·닫기와 검색·필터 동작을 `admin-ui.js`로 통합하고 `admin.css`에 반응형 모달과 툴바 스타일을 추가했습니다.
- **공통코드 상태 전환**: 메타데이터를 유지한 채 `POST /codes`로 전송하는 비활성화·재활성화 확인 모달을 추가했으며, 물리 삭제 금지 규칙(`DELETE /codes`, `POST /codes/delete`의 `405 COMMON_CODE_DELETE_FORBIDDEN`)은 그대로 유지합니다.
- **다국어 문구 및 버전 정렬**: `admin.properties`와 `admin_ko.properties`에 모달·검색·건수·비활성화/재활성화 문구를 100% 영/한 키 대칭으로 추가하고, Gradle 빌드, MCP 서버 메타데이터, 클라이언트 훅 매니페스트 버전을 `2.1.1`로 정렬했습니다.

### 제거

이 릴리스에서 제거된 기능, 엔드포인트, CLI 명령, MCP 도구 또는 설정은 없습니다.

### 보안

- 모든 템플릿에서 인라인 `<script>`, `<style>`, `style=`, `on*=` 핸들러가 없는 엄격한 콘텐츠 보안 정책을 유지합니다(`ArchitectureTest`, `SecurityHeadersTest`).
- `POST /grants/sync`와 `POST /grants/tokens`는 다른 모든 관리 웹 변경 엔드포인트와 동일한 소유자 패스키 승인 및 CSRF 보호를 적용하며, 세션 키 등록·교체 전 `/grants/preview` 지문 확인 절차를 필수로 유지합니다.
- `ROLE_ENROLL` 등록 전용 세션은 패스키 등록으로 계속 제한됩니다.

### 요구 사항

- 서버 호스트 및 클라이언트 훅 호스트의 Java 25 런타임(`JDK 25`).
- 기존 `2.1.0` PostgreSQL 데이터베이스(스키마 `V11`) 및 등록된 JDBC 드라이버. 추가 런타임 의존성이나 외부 프론트엔드 빌드 도구는 필요하지 않습니다.

### 알려진 제한

- 자동 회귀 시험은 MockMvc 렌더링, CSP 헤더, 다국어 키 대칭, HTTP·폼 계약을 검증하며, 호스트 훅이 브라우저 서브에이전트의 MCP 호출을 차단하는 환경에서는 데스크톱·모바일 실브라우저 육안 점검을 별도로 수행해야 합니다.
