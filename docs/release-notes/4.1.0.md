# veridger 4.1.0

## English

### Summary

`4.1.0` is a backward-compatible minor release focusing on operator UX, one-stop installation, and least-privilege self-updates (`Schema-Version: V11`). The admin web `/grants` console now separates the host selector from the session ID input while preserving the stored `<vendor>:<session-id>` identifier and `V11` database schema. The server installers (`deploy/install.sh` and `deploy\install.cmd`) now support verified release downloads and guided interactive prompts alongside new client hook installers (`deploy/install-hook.sh` and `deploy\install-hook.cmd`). Finally, the admin web adds a `/updates` console backed by external host updaters (`deploy/veridger-updater.sh` and `deploy\veridger-updater.cmd`) with `SHA256SUMS` verification, schema-change guards, `/healthz` checks, and automatic rollback.

### Breaking changes

There are no breaking changes in this release. Existing `4.0.1` MCP servers, admin web installations, database schemas (`V11`), CLI commands, client hooks, and non-interactive installer invocations remain fully compatible.

### Migration

1. Build the `4.1.0` jars with `./gradlew assemble` (no test database required) or let the enhanced `deploy/install.sh` (without `--jars`) or `deploy\install.cmd` (`--download`) fetch and verify `SHA256SUMS` from the `4.1.0` release.
2. Re-run `deploy/install.sh` or `deploy\install.cmd` to update the service jars and install the least-privilege host updater (`deploy/veridger-updater.sh` or `deploy\veridger-updater.cmd`). Because the schema stays at `V11`, no database migration is required beyond standard `ledger-cli setup`.
3. For client hosts, run `deploy/install-hook.sh` or `deploy\install-hook.cmd` to download, verify `SHA256SUMS`, merge Codex/Claude/Antigravity hook configurations with backups, and smoke-test the hook.
4. Future minor/patch releases can be staged directly from the admin web `/updates` page. To roll back manually, restore the previous jars or let the host updater roll back automatically (`ROLLED_BACK`) if `/healthz` fails.

### New

- **Split Host + Session ID UI on `/grants` (`SessionAuthorInput`)**: Separates the host selector (configurable via `ledger.admin.grants.known-hosts` plus custom host input) and session ID input on `/grants` cards and modals, with automatic splitting when pasting `<vendor>:<session-id>` and zero changes to the `V11` database schema.
- **One-stop server & client hook installers**: Enhanced `deploy/install.sh` (`--version`, `--repo`, auto-download when `--jars` is omitted, interactive prompts) and `deploy\install.cmd` (`--download` interactive mode), and added `deploy/install-hook.sh` and `deploy\install-hook.cmd` for guided Codex, Claude Code, and Antigravity hook installation.
- **Admin Web `/updates` console and least-privilege host updaters**: Added `/updates` (`ledger.admin.update.*`) to query GitHub Releases, verify `SHA256SUMS`, block major or schema-changing releases for manual `ledger-cli setup`, and stage `request.properties` for `deploy/veridger-updater.sh` (systemd path/service) and `deploy\veridger-updater.cmd` (Scheduled Task), which replace jars, restart services, verify `/healthz`, record `status.properties`, and roll back (`ROLLED_BACK`) on failure.

### Changed

- **Backward-compatible form handling on `/grants`**: Single-field `<vendor>:<session-id>` requests continue to work alongside the split host and session ID inputs, preserving existing automation and HTTP contracts.
- **Release version alignment**: Aligned Gradle build metadata, MCP server metadata, and all three client plugin manifests to `4.1.0`.

### Removed

No features, endpoints, CLI commands, MCP tools, or settings were removed in this release.

### Security

- The admin web JVM never invokes `ProcessBuilder` or OS commands: it only downloads artifacts from allowed hosts, verifies `SHA256SUMS`, rejects symlinks (`NOFOLLOW_LINKS`), and writes an atomic update request under the update directory behind owner session and CSRF protection.
- Both `deploy/veridger-updater.sh` and `deploy\veridger-updater.cmd` reject symlinks, copy staged jars into a privileged private temp directory before fetching authoritative `SHA256SUMS` over HTTPS from the pinned repository and verifying every digest against both `SHA256SUMS` and `request.properties`, and automatically roll back (`ROLLED_BACK`) if `/healthz` fails after restart.
- Releases whose notes require a newer database schema than `V11` or a major version bump are refused from one-click staging and direct the owner to run `ledger-cli setup` manually.

### Requirements

- Java 25 runtime (`JDK 25`) on server and client hosts.
- Existing PostgreSQL database on `Schema-Version: V11`.

### Known limitations

- Self-updates from `/updates` require the host updater (`deploy/veridger-updater.sh` or `deploy\veridger-updater.cmd`) to be installed by re-running `deploy/install.sh` or `deploy\install.cmd` once on `4.1.0`.
- Releases that introduce a new database schema migration beyond `V11` or a new major version still require manual `ledger-cli setup` because the runtime services never hold DDL credentials.

## 한국어

### 요약

`4.1.0`은 운영자 UX, 원스톱 설치, 최소 권한 자체 업데이트에 초점을 맞춘 하위 호환 마이너 릴리스입니다(`Schema-Version: V11`). 관리 웹 `/grants` 콘솔은 저장되는 `<vendor>:<session-id>` 식별자와 `V11` 데이터베이스 스키마를 유지하면서 호스트 선택과 세션 ID 입력을 분리했습니다. 서버 설치기(`deploy/install.sh`, `deploy\install.cmd`)는 검증된 릴리스 내려받기와 대화형 입력을 지원하며, 새로운 클라이언트 훅 설치기(`deploy/install-hook.sh`, `deploy\install-hook.cmd`)가 추가되었습니다. 또한 관리 웹에 `/updates` 콘솔이 추가되어 외부 호스트 업데이터(`deploy/veridger-updater.sh`, `deploy\veridger-updater.cmd`)와 연동해 `SHA256SUMS` 검증, 스키마 변경 차단, `/healthz` 확인 및 자동 롤백을 제공합니다.

### 호환되지 않는 변경

이 릴리스에는 호환되지 않는 변경이 없습니다. 기존 `4.0.1` MCP 서버, 관리 웹 설치, 데이터베이스 스키마(`V11`), CLI 명령, 클라이언트 훅 및 비대화형 설치기 호출은 모두 그대로 호환됩니다.

### 이전 절차

1. `./gradlew assemble`(시험 데이터베이스 불필요)로 `4.1.0` JAR를 빌드하거나, 개선된 `deploy/install.sh`(`--jars` 생략) 또는 `deploy\install.cmd`(`--download`)로 `4.1.0` 릴리스에서 `SHA256SUMS`를 검증하며 내려받습니다.
2. `deploy/install.sh` 또는 `deploy\install.cmd`를 다시 실행해 서비스 JAR를 갱신하고 최소 권한 호스트 업데이터(`deploy/veridger-updater.sh` 또는 `deploy\veridger-updater.cmd`)를 설치합니다. 스키마는 `V11` 그대로이므로 일반 `ledger-cli setup` 외 별도 DB 마이그레이션은 필요하지 않습니다.
3. 클라이언트 호스트에서는 `deploy/install-hook.sh` 또는 `deploy\install-hook.cmd`를 실행해 훅 JAR를 내려받아 `SHA256SUMS`를 검증하고 백업을 남기며 Codex/Claude/Antigravity 설정을 병합한 뒤 스모크 테스트를 수행합니다.
4. 이후의 마이너·패치 릴리스는 관리 웹 `/updates` 화면에서 바로 예약할 수 있습니다. 수동 롤백 시 이전 JAR를 복원하거나, `/healthz` 실패 시 호스트 업데이터의 자동 롤백(`ROLLED_BACK`)에 맡길 수 있습니다.

### 추가

- **`/grants` 호스트·세션 ID 분리 UI (`SessionAuthorInput`)**: `V11` 데이터베이스 스키마 변경 없이 `/grants` 카드와 모달에서 호스트 선택(`ledger.admin.grants.known-hosts` 설정 및 직접 입력 지원)과 세션 ID 입력을 분리했으며, `<vendor>:<session-id>` 붙여넣기 시 자동 분리를 지원합니다.
- **원스톱 서버·클라이언트 훅 설치기**: `deploy/install.sh`(`--version`, `--repo`, `--jars` 생략 시 자동 내려받기, 대화형 입력)와 `deploy\install.cmd`(`--download` 대화형 모드)를 확장하고, Codex·Claude Code·Antigravity 훅 안내형 설치기 `deploy/install-hook.sh` 및 `deploy\install-hook.cmd`를 추가했습니다.
- **관리 웹 `/updates` 콘솔 및 최소 권한 호스트 업데이터**: `/updates`(`ledger.admin.update.*`)에서 GitHub Releases 조회, `SHA256SUMS` 검증, 메이저·스키마 변경 릴리스의 수동 `ledger-cli setup` 차단 안내, `request.properties` 스테이징을 제공하며 `deploy/veridger-updater.sh`(systemd path/service)와 `deploy\veridger-updater.cmd`(작업 스케줄러)가 JAR 교체·서비스 재시작·`/healthz` 확인·`status.properties` 기록 및 실패 시 자동 롤백(`ROLLED_BACK`)을 수행합니다.

### 변경

- **`/grants` 하위 호환 폼 처리**: 호스트·세션 ID 분리 입력과 함께 기존 단일 필드 `<vendor>:<session-id>` 요청도 계속 지원해 기존 자동화와 HTTP 계약을 유지합니다.
- **릴리스 버전 정렬**: Gradle 빌드 메타데이터, MCP 서버 메타데이터, 클라이언트 플러그인 매니페스트 3종의 버전을 `4.1.0`으로 정렬했습니다.

### 제거

이 릴리스에서 제거된 기능, 엔드포인트, CLI 명령, MCP 도구 또는 설정은 없습니다.

### 보안

- 관리 웹 JVM은 `ProcessBuilder`나 OS 명령을 직접 실행하지 않으며, 소유자 세션과 CSRF 보호 아래 허용된 호스트에서만 아티팩트를 내려받아 `SHA256SUMS` 검증과 심볼릭 링크 차단(`NOFOLLOW_LINKS`)을 거쳐 업데이트 디렉터리에 요청을 원자적으로 기록합니다.
- `deploy/veridger-updater.sh`와 `deploy\veridger-updater.cmd`는 심볼릭 링크를 거부하고 스테이징된 JAR를 권한 격리된 임시 디렉터리로 복사한 뒤 고정된 저장소에서 HTTPS로 공식 `SHA256SUMS`를 직접 받아 `SHA256SUMS`와 `request.properties` 모두를 검증하며, 재시작 후 `/healthz`가 실패하면 자동으로 롤백(`ROLLED_BACK`)합니다.
- `V11`보다 새로운 데이터베이스 스키마나 메이저 업그레이드가 필요한 릴리스는 원클릭 스테이징을 차단하고 소유자에게 수동 `ledger-cli setup` 실행을 안내합니다.

### 요구 사항

- 서버 호스트 및 클라이언트 호스트의 Java 25 런타임(`JDK 25`).
- `Schema-Version: V11` 기반 기존 PostgreSQL 데이터베이스.

### 알려진 제한

- `/updates`를 통한 자체 업데이트를 사용하려면 `4.1.0`에서 `deploy/install.sh` 또는 `deploy\install.cmd`를 한 번 실행해 호스트 업데이터(`deploy/veridger-updater.sh` 또는 `deploy\veridger-updater.cmd`)를 설치해야 합니다.
- 런타임 서비스는 DDL 자격 증명을 보관하지 않으므로, `V11` 이후 새 스키마 마이그레이션이나 메이저 업그레이드를 포함한 릴리스는 여전히 수동 `ledger-cli setup`이 필요합니다.
