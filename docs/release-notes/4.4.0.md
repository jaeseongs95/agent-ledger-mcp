# veridger 4.4.0

## English

### Summary

The `4.4.0` minor release adds date search, project renaming and more precise permissions filters to the administration console. It introduces `Schema-Version: V14`.

### Breaking changes

The services require `Schema-Version: V14` at startup. Installations on `Schema-Version: V13` must apply the migration before starting the new services. Existing MCP clients can continue using their installed hooks.

### Migration

1. Download the `4.4.0` server JARs and verify them against `SHA256SUMS`.
2. Stop both services and back up the database, installed JARs and deployment configuration.
3. With the new CLI and the database owner credentials, run `ledger-cli migrate --owner-account=<owner> --app-account=<app>` to apply `V14__project_display_name_and_date_indexes.sql`. Confirm that V14 succeeded.
4. Install the verified JARs, start both services and verify `/healthz`. Confirm that the projects and grants still appear in the console.
5. To return to `4.3.2`, stop both services and restore the V13 database backup and matching JARs before starting the services. The backup covers data up to the point when the services were stopped for the upgrade.

### New

- Issues, specifications, tasks and release gates have sortable registration and last-modified dates. History has a sortable event date. Date-only search uses the calendar days of the browser's time zone.
- The Projects page supports renaming projects. The migration initializes display names from the existing codes in the `project` table. The project ID, code used as an entity ID prefix, counters and grants retain their values.
- The Grants page filters by project name, session ID, host and permission.

### Changed

The Projects list shows the project name and description. Dates are displayed in the browser's time zone and compared in UTC.

### Removed

The sidebar entry for Common Codes has been removed.

### Security

Project renaming requires an authenticated owner session and records the change in the owner audit trail.

### Requirements

- `JDK 25` for the server and client hook runtimes.
- Database on `Schema-Version: V14`.

### Known limitations

The previous release's `/updates` page requires a manual upgrade because the database schema changes. A release gate shows a blank date when its history does not contain a corresponding event.

## 한국어

### 요약

`4.4.0` 부 버전은 관리 콘솔에 날짜 검색, 프로젝트명 변경, 세분화된 권한 필터를 추가합니다. `Schema-Version: V14`를 도입합니다.

### 호환되지 않는 변경

서비스 기동에는 `Schema-Version: V14`가 필요합니다. `Schema-Version: V13` 설치 환경은 새 서비스를 시작하기 전에 마이그레이션을 적용해야 합니다. 기존 MCP 클라이언트는 설치된 훅을 계속 사용할 수 있습니다.

### 이전 절차

1. `4.4.0` 서버 JAR를 내려받아 `SHA256SUMS`로 검증합니다.
2. 두 서비스를 중지하고 데이터베이스, 설치된 JAR와 배포 설정을 백업합니다.
3. 새 CLI와 데이터베이스 소유자 자격 증명으로 `ledger-cli migrate --owner-account=<owner> --app-account=<app>`를 실행해 `V14__project_display_name_and_date_indexes.sql`을 적용합니다. V14 적용 성공을 확인합니다.
4. 검증한 JAR를 설치하고 두 서비스를 기동한 후 `/healthz`를 확인합니다. 관리 콘솔에서 프로젝트와 권한이 표시되는지 확인합니다.
5. `4.3.2`로 되돌리려면 두 서비스를 중지하고 V13 데이터베이스 백업과 해당 버전의 JAR를 복원한 후 서비스를 시작합니다. 백업에는 업그레이드를 위해 서비스를 중지한 시점까지의 데이터가 포함됩니다.

### 추가

- 이슈·명세·작업·출시기준 목록에 등록일과 마지막 수정일 정렬을 추가했습니다. 이력은 이벤트 발생일로 정렬할 수 있습니다. 날짜 검색은 브라우저 시간대의 달력 날짜를 사용합니다.
- 프로젝트 화면에서 이름을 변경할 수 있습니다. 마이그레이션은 `project` 테이블의 기존 코드로 표시 이름을 초기화합니다. 프로젝트 ID, 항목 ID 접두어로 쓰는 코드, 번호 카운터와 부여된 권한은 기존 값을 유지합니다.
- 부여 화면에 프로젝트명, 세션 ID, 호스트, 권한 필터를 추가했습니다.

### 변경

프로젝트 목록에 프로젝트명과 설명을 표시합니다. 날짜는 브라우저 시간대로 표시하고 UTC로 비교합니다.

### 제거

사이드바에서 공통코드 메뉴를 제거했습니다.

### 보안

프로젝트명 변경에는 인증된 소유자 세션이 필요하며, 변경 사항은 소유자 감사 이력에 기록합니다.

### 요구 사항

- 서버와 클라이언트 훅의 실행 환경에 `JDK 25`가 필요합니다.
- 데이터베이스에 `Schema-Version: V14`가 필요합니다.

### 알려진 제한

데이터베이스 스키마가 바뀌므로 이전 버전의 `/updates` 화면에서 안내하는 수동 업그레이드가 필요합니다. 출시기준의 이력에 해당 이벤트가 없으면 날짜를 빈 값으로 표시합니다.
