# veridger 4.2.0

## English

### Summary

`4.2.0` is a backward-compatible minor release dedicated to end-to-end performance optimization across the database layer (`Schema-Version: V12`), write/batch/detail/transition pipelines, attachment decryption streaming, MCP server runtime, admin web console, and client hooks. It introduces 14 ANSI secondary indexes (`V12__performance_indexes.sql`), rewrites key queries to eliminate full scans and O(N) round-trips, collapses batch ID/history/receipt I/O into bulk operations, converts attachment downloads from O(S^2) repeated channel opens to single-pass O(S) streaming (`AttachmentStore.stream`), enables Java 25 virtual threads and HTTP response compression, adds revision-cohered `CommonCodeRepository` caching and 5-minute TTL release-check caching, and trims client hook startup and per-call overhead.

### Breaking changes

There are no breaking API, MCP tool contract, CLI, or client hook protocol changes in this release. Existing `4.1.0` clients and hooks remain compatible. Because `4.2.0` adds database migration `V12__performance_indexes.sql` (`Schema-Version: V12`), operators must run `ledger-cli migrate` (or `ledger-cli setup`) before starting the `4.2.0` server JARs.

### Migration

1. Build the `4.2.0` jars with `./gradlew assemble` or download and verify `SHA256SUMS` from the `4.2.0` release.
2. Stop the running `4.1.0` services and run `ledger-cli migrate` (using the DDL account) to apply `V12__performance_indexes.sql` (`Schema-Version: V12`). Because `4.1.0` admin web `/updates` intentionally blocks schema-changing releases, upgrade via `deploy/install.sh` or `deploy\install.cmd` (or replace the JARs after `ledger-cli migrate`).
3. Start the `4.2.0` MCP server and admin web services and verify `/healthz`.
4. Optionally update client hooks via `deploy/install-hook.sh` or `deploy\install-hook.cmd` to gain shallow argument stamping, fast-path non-Veridger skip, and lazy account lookup.
5. Roll back by restoring the `4.1.0` JARs; all 14 indexes in `V12__performance_indexes.sql` are strictly additive and safe to leave in place if rolling back.

### New

- **ANSI secondary index migration (`V12__performance_indexes.sql`)**: Adds 14 vendor-neutral, plain-column secondary indexes covering `criterion_link`, `issue_task`, `issue_spec`, `spec_task`, `issue_relation`, `history`, `task`, `milestone_criterion`, `session_grant`, and `deliverable`.
- **Single-pass O(S) attachment decryption streaming (`AttachmentStore.stream`)**: Opens one file channel, precomputes AAD prefix once per file (`SegmentCipher`), and verifies/streams every encrypted segment linearly to the HTTP response stream instead of re-opening and re-reading earlier segments on every 256 KiB page.
- **Bulk range allocation and batched receipt completion**: Added `IdAllocator.reserveRange`, `HistoryWriter.appendAll` (reserving contiguous history IDs in a single range update), and `ReceiptCompletionRepository.finishAll` (JDBC `batchUpdate` on drivers with exact per-row batch counts, with fail-closed per-row fallback otherwise).
- **Single-round-trip lookups and count queries**: Added `EntityLookupRepository.findAny`, `EntityLookupRepository.taskSummaries`, `AttentionQueryRepository.counts`, and single-table `StatsQueryRepository` counters (`countIssues`, `countSpecs`, `countTasks`, `countCriteria`).
- **Configurable JDBC pool timing properties**: Added `ledger.jdbc.connection-timeout-ms`, `ledger.jdbc.idle-timeout-ms`, and `ledger.jdbc.keepalive-time-ms` in `LedgerJdbcProperties` and `DriverDataSources`.
- **Bounded MCP session retention & OOM crash-fast recovery**: Added `McpTransportConfiguration` and `LedgerMcpProperties` settings (`ledger.mcp.session-idle-timeout` default `30m`, `ledger.mcp.max-sessions` default `1000`, `ledger.mcp.keep-alive-interval` default `30s`) so disconnected Streamable HTTP sessions are evicted instead of accumulating in heap; added `-XX:+ExitOnOutOfMemoryError` to `JvmPreset.SERVICE_OPTIONS` for managed `systemd` and WinSW services so supervisor auto-restart recovers cleanly if OOM ever occurs.

### Changed

- **Query and index-usage rewrites**: Rewrote `GrantStateRepository` (`hasLive`/`markUsed`) to hit `active_key` directly, `LinkRepository.relationsOf` to disjoint `UNION ALL` over indexed `a`/`b` columns, `IssueQueryRepository` owner filtering to short-circuit `owner_actor_id` before deliverable lookup, `HistoryQueryRepository` to narrow project scans by entity filter and prefix-gate deliverable subqueries, and `AttentionQueryRepository` / `SearchQueryRepository` to push keyset and project predicates into each branch.
- **Reduced per-request DB round-trips in application services**: `WriteOperation` loads `request_receipt` once per write and skips redundant `hasLive` checks for already-authorized batch targets; `TransitionOperation` reuses already-loaded history rows and eliminates duplicate post-pin entity re-reads; `DetailService` reads lightweight history projections (`HistoryQueryRepository.transitionsOfEntity` and `newestSummariesOfEntity`, omitting `before_data` and `changes` JSON blobs) and batch-loads linked task summaries; `GetService` resolves mixed IDs in one `findAny` round-trip.
- **Revision-cohered `CommonCodeRepository` cache**: Caches common-code snapshots keyed by `code_revision` in an instance-scoped `AtomicReference`, bypassing cache inside active read-write transactions and invalidating on writes.
- **Canonical JSON & MCP runtime optimizations**: Added safe-integer fast-path and fused zero-clone argument canonicalization in `JsonCanonicalizer` and `ArgumentsDigest`; precomputed `ToolBinding` parameter metadata; eliminated redundant hex round-trip in `AgentTokenProvider`; enabled `spring.threads.virtual.enabled` and HTTP response compression (`application/json`, `text/plain`, excluding `text/event-stream`) in `ledger-mcp-server`.
- **Admin Web responsiveness**: `/overview` uses bounded `AttentionService.counts`; list controllers use single-table counters instead of full stats aggregation; `AttachmentPanels` deduplicates panel lookups per attachment ID and streams via `AttachmentStore.stream`; `UpdateService.inspect()` caches GitHub Release metadata for 5 minutes using the injected `Clock` while `applyLatest()` always fetches live; enabled HTTP response compression and static asset `Cache-Control`.
- **Client hook latency & allocation trim**: Replaced `arguments.deepCopy()` with shallow top-level copy in `LedgerHook`, added fast-path skip for non-Veridger `call_mcp_tool` calls in `AntigravityDialect`, made user account lookup lazy in `ledger-hook-client` (`Main`, `ClientEnvironment`), and removed regex splitting in `AddressFile` and lambda allocations in `ResidentFinder`.

### Removed

No features, endpoints, CLI commands, MCP tools, or settings were removed in this release.

### Security

- All optimizations preserve existing authorization, receipt idempotency, anti-spoofing, and cryptographic verification guarantees (`SegmentCipher` verifies every segment tag and trailing end mark during `AttachmentStore.stream`).
- `CommonCodeRepository` and `UpdateService` caches are strictly instance-scoped (`AtomicReference`, zero `ThreadLocal` or mutable statics), bypass uncommitted write transactions, and `UpdateService.applyLatest()` always performs a live release fetch and `SHA256SUMS` verification before staging.
- HTTP compression on `ledger-mcp-server` explicitly excludes `text/event-stream` so SSE streams are not buffered or exposed to cross-event compression issues.

### Requirements

- Java 25 runtime (`JDK 25`) on server and client hosts.
- Database migrated to `Schema-Version: V12` via `ledger-cli migrate`.

### Known limitations

- Upgrading from `4.1.0` to `4.2.0` cannot be triggered from the admin web `/updates` button because `V12__performance_indexes.sql` bumps the schema version from `V11` to `V12`; run `ledger-cli migrate` with DDL credentials before starting `4.2.0`.
- Warm per-invocation hook latency remains bounded primarily by JVM startup of the short-lived `ledger-client-hook.jar` process (~100 ms on JDK 25 with `-XX:+UseSerialGC -XX:TieredStopAtLevel=1`).

## 한국어

### 요약

`4.2.0`은 데이터베이스 계층(`Schema-Version: V12`), 쓰기·배치·상세·전이 파이프라인, 첨부 복호화 스트리밍, MCP 서버 런타임, 관리 웹 콘솔, 클라이언트 훅 전반의 성능을 개선한 하위 호환 마이너 릴리스입니다. 14개의 ANSI 보조 인덱스(`V12__performance_indexes.sql`)를 추가하고, 풀 스캔과 O(N) 왕복을 제거하도록 핵심 쿼리를 재작성했으며, 배치 ID·이력·영수증 I/O를 일괄 처리로 통합했습니다. 또한 첨부 내려받기를 O(S^2) 반복 채널 열기에서 단일 패스 O(S) 스트리밍(`AttachmentStore.stream`)으로 전환하고, Java 25 가상 스레드와 HTTP 응답 압축, 리비전 정합 `CommonCodeRepository` 캐시, 5분 TTL 릴리스 조회 캐시, 클라이언트 훅 기동·호출 오버헤드 절감을 적용했습니다.

### 호환되지 않는 변경

이 릴리스에는 호환되지 않는 API, MCP 도구 계약, CLI 또는 클라이언트 훅 프로토콜 변경이 없습니다. 기존 `4.1.0` 클라이언트와 훅도 그대로 호환됩니다. 다만 `4.2.0`은 데이터베이스 마이그레이션 `V12__performance_indexes.sql`(`Schema-Version: V12`)을 추가하므로, `4.2.0` 서버 JAR를 기동하기 전에 `ledger-cli migrate`(또는 `ledger-cli setup`)를 실행해야 합니다.

### 이전 절차

1. `./gradlew assemble`로 `4.2.0` JAR를 빌드하거나 `4.2.0` 릴리스에서 내려받아 `SHA256SUMS`를 검증합니다.
2. 실행 중인 `4.1.0` 서비스를 중지하고 DDL 계정으로 `ledger-cli migrate`를 실행해 `V12__performance_indexes.sql`(`Schema-Version: V12`)을 적용합니다. `4.1.0` 관리 웹 `/updates`는 스키마 변경 릴리스를 의도적으로 차단하므로 `deploy/install.sh` 또는 `deploy\install.cmd`를 사용하거나 `ledger-cli migrate` 후 JAR를 교체합니다.
3. `4.2.0` MCP 서버와 관리 웹 서비스를 시작하고 `/healthz`를 확인합니다.
4. 선택적으로 `deploy/install-hook.sh` 또는 `deploy\install-hook.cmd`를 실행해 얕은 인자 복사, 비-Veridger 빠른 건너뛰기, 지연 계정 조회가 반영된 클라이언트 훅으로 갱신합니다.
5. 롤백 시 `4.1.0` JAR를 복원하면 됩니다. `V12__performance_indexes.sql`의 14개 인덱스는 순수 추가 인덱스이므로 롤백 후 남겨 두어도 안전합니다.

### 추가

- **ANSI 보조 인덱스 마이그레이션 (`V12__performance_indexes.sql`)**: `criterion_link`, `issue_task`, `issue_spec`, `spec_task`, `issue_relation`, `history`, `task`, `milestone_criterion`, `session_grant`, `deliverable`에 벤더 비종속 일반 컬럼 보조 인덱스 14개를 추가했습니다.
- **단일 패스 O(S) 첨부 복호화 스트리밍 (`AttachmentStore.stream`)**: 256 KiB 페이지마다 파일을 다시 열고 앞선 세그먼트를 반복 읽기하던 구조를 파일 채널 1회 열기, 파일당 1회 AAD 접두사 계산(`SegmentCipher`), 전체 세그먼트 선형 검증·스트리밍으로 개선했습니다.
- **ID 범위 일괄 할당 및 영수증 일괄 완료**: `IdAllocator.reserveRange`, `HistoryWriter.appendAll`(연속 이력 ID를 단일 범위 갱신으로 예약), `ReceiptCompletionRepository.finishAll`(정확한 행별 배치 카운트를 반환하는 드라이버에서 JDBC `batchUpdate`, 그 외 드라이버는 fail-closed 건별 폴백)를 추가했습니다.
- **단일 왕복 조회 및 카운트 쿼리**: `EntityLookupRepository.findAny`, `EntityLookupRepository.taskSummaries`, `AttentionQueryRepository.counts`, 단일 테이블 `StatsQueryRepository` 카운터(`countIssues`, `countSpecs`, `countTasks`, `countCriteria`)를 추가했습니다.
- **JDBC 커넥션 풀 타이밍 설정**: `LedgerJdbcProperties`와 `DriverDataSources`에 `ledger.jdbc.connection-timeout-ms`, `ledger.jdbc.idle-timeout-ms`, `ledger.jdbc.keepalive-time-ms` 설정을 추가했습니다.
- **MCP 세션 상한·유휴 만료 및 OOM 즉시 복구**: `McpTransportConfiguration`과 `LedgerMcpProperties` 설정(`ledger.mcp.session-idle-timeout` 기본 `30m`, `ledger.mcp.max-sessions` 기본 `1000`, `ledger.mcp.keep-alive-interval` 기본 `30s`)을 추가해 비정상 종료된 Streamable HTTP 세션이 힙에 누적되지 않도록 자동 정리하고, `JvmPreset.SERVICE_OPTIONS`에 `-XX:+ExitOnOutOfMemoryError`를 추가해 `systemd`와 WinSW 관리 서비스가 OOM 시 좀비 상태로 남지 않고 자동 재시작되도록 개선했습니다.

### 변경

- **쿼리 및 인덱스 활용 재작성**: `GrantStateRepository`(`hasLive`/`markUsed`)가 `active_key`를 직접 조회하도록 바꾸고, `LinkRepository.relationsOf`를 인덱스된 `a`/`b` 컬럼의 비중첩 `UNION ALL`로 재작성했으며, `IssueQueryRepository` 소유자 필터가 `owner_actor_id`를 먼저 단락 평가하도록 개선했습니다. 또한 `HistoryQueryRepository`의 프로젝트 필터 범위를 엔티티 필터에 맞춰 좁히고 산출물 서브쿼리에 접두사 가드를 적용했으며, `AttentionQueryRepository`와 `SearchQueryRepository`의 키셋·프로젝트 조건을 각 분기 내부로 푸시다운했습니다.
- **애플리케이션 서비스 DB 왕복 절감**: `WriteOperation`이 `request_receipt`를 쓰기당 1회만 읽고 이미 인가된 배치 대상의 중복 `hasLive` 검사를 생략하며, `TransitionOperation`이 이미 읽은 이력 행을 재사용하고 핀 이후 중복 엔티티 재조회를 제거했습니다. `DetailService`는 경량 이력 프로젝션(`HistoryQueryRepository.transitionsOfEntity` 및 `newestSummariesOfEntity`로 `before_data`·`changes` JSON 제외)과 연결 작업 요약을 일괄 조회하고, `GetService`는 혼합 ID를 `findAny` 1회 왕복으로 해결합니다.
- **리비전 정합 `CommonCodeRepository` 캐시**: 인스턴스 범위 `AtomicReference`에 `code_revision` 기반 공통 코드 스냅샷을 캐시하되, 활성 읽기-쓰기 트랜잭션 내부에서는 캐시를 우회하고 쓰기 시 즉시 무효화합니다.
- **정규 JSON 및 MCP 런타임 최적화**: `JsonCanonicalizer`와 `ArgumentsDigest`에 안전 정수 고속 경로와 무복사 단일 패스 인자 정규화를 추가했고, `ToolBinding` 파라미터 메타데이터를 사전 계산했으며, `AgentTokenProvider`의 불필요한 16진수 왕복을 제거했습니다. `ledger-mcp-server`에는 `spring.threads.virtual.enabled`와 HTTP 응답 압축(`application/json`, `text/plain`, `text/event-stream` 제외)을 활성화했습니다.
- **관리 웹 응답성 개선**: `/overview`가 상한이 있는 `AttentionService.counts`를 사용하고 목록 컨트롤러가 전체 통계 집계 대신 단일 테이블 카운터를 사용하도록 변경했습니다. `AttachmentPanels`는 첨부 ID별 패널 조회를 중복 제거하고 `AttachmentStore.stream`으로 스트리밍하며, `UpdateService.inspect()`는 주입된 `Clock`으로 GitHub 릴리스 메타데이터를 5분간 캐시(`applyLatest()`는 항상 실시간 조회)합니다. 또한 HTTP 응답 압축과 정적 자산 `Cache-Control`을 활성화했습니다.
- **클라이언트 훅 지연 및 할당 절감**: `LedgerHook`의 `arguments.deepCopy()`를 최상위 얕은 복사로 교체하고, `AntigravityDialect`에서 비-Veridger `call_mcp_tool` 호출을 빠르게 건너뛰도록 했으며, `ledger-hook-client`(`Main`, `ClientEnvironment`)의 계정 조회를 지연 평가로 바꾸고 `AddressFile` 정규식 분할과 `ResidentFinder` 람다 할당을 제거했습니다.

### 제거

이 릴리스에서 제거된 기능, 엔드포인트, CLI 명령, MCP 도구 또는 설정은 없습니다.

### 보안

- 모든 최적화는 기존 인가, 영수증 멱등성, 위조 방지, 암호화 검증 보장을 그대로 유지합니다(`SegmentCipher`는 `AttachmentStore.stream` 중 모든 세그먼트 태그와 종료 마커를 검증합니다).
- `CommonCodeRepository`와 `UpdateService` 캐시는 엄격한 인스턴스 범위(`AtomicReference`, `ThreadLocal` 및 가변 정적 필드 없음)이며, 커밋되지 않은 쓰기 트랜잭션을 우회하고 `UpdateService.applyLatest()`는 스테이징 전 항상 실시간 릴리스 조회와 `SHA256SUMS` 검증을 수행합니다.
- `ledger-mcp-server`의 HTTP 압축은 `text/event-stream`을 명시적으로 제외해 SSE 스트림 버퍼링이나 교차 이벤트 압축 노출을 방지합니다.

### 요구 사항

- 서버 호스트 및 클라이언트 호스트의 Java 25 런타임(`JDK 25`).
- `ledger-cli migrate`로 `Schema-Version: V12`까지 마이그레이션된 데이터베이스.

### 알려진 제한

- `V12__performance_indexes.sql`이 스키마 버전을 `V11`에서 `V12`로 올리므로, `4.1.0`에서 `4.2.0`으로의 업그레이드는 관리 웹 `/updates` 버튼으로 바로 적용할 수 없으며 `4.2.0` 기동 전에 DDL 자격 증명으로 `ledger-cli migrate`를 실행해야 합니다.
- 클라이언트 훅의 웜 호출 지연은 단기 실행되는 `ledger-client-hook.jar` JVM 기동 시간(~100 ms, JDK 25 `-XX:+UseSerialGC -XX:TieredStopAtLevel=1` 기준)이 주된 하한으로 남습니다.
