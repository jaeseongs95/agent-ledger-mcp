# veridger 4.4.1

## English

### Summary

The `4.4.1` patch improves navigation, readability and keyboard access in the administration console, especially for projects with many release gates, milestones or history entries.

### Breaking changes

The release preserves the existing client contract, deployment settings and database schema.

### Migration

1. On an installation already running `4.4.0` with `Schema-Version: V14`, select `4.4.1` in the `/updates` page and apply it. The host updater checks the release JARs against `SHA256SUMS`, backs up the installed JARs and restarts both services.
2. Confirm the updater reports `SUCCEEDED` and both services report `UP` at `/healthz`. Open the console and check the redesigned overview and release gates.
3. If the health checks fail, confirm the updater reports `ROLLED_BACK`. For a manual rollback on the default Linux instance, run `sudo systemctl stop veridger veridger-admin`, restore the backed-up `4.4.0` JARs and the `.installed-version` marker in `/opt/veridger`, and run `sudo systemctl start veridger veridger-admin`. Confirm both services report `UP` at `/healthz`.

### New

The console shows its current section in the header and provides keyboard access to the mobile navigation drawer and record tables.

### Changed

- The overview places MCP status, project selection and work counts above the review queue.
- The record filters group date criteria in an expandable control. Release gates place filters above a collapsible milestone summary. Release gates and history provide pagination above and below multi-page results.
- Long release gate identifiers and long text have compact previews. The full text and raw history JSON are available on demand.
- The session grant filter and summary adapt to narrow viewports and long session IDs.

### Removed

The console consolidates duplicate release gate history links into the Recent Changes section.

### Security

The admin authentication and permission requirements remain in effect.

### Requirements

- The server and client hooks require `JDK 25`.
- The database requires `Schema-Version: V14`.

### Known limitations

Wide record tables can require horizontal scrolling on narrow viewports.

## 한국어

### 요약

`4.4.1` 패치는 관리 콘솔의 탐색, 가독성과 키보드 접근성을 개선합니다. 출시 기준과 마일스톤, 이력이 많은 프로젝트에서 주요 정보를 찾기 쉽도록 배치를 조정했습니다.

### 호환되지 않는 변경

기존 클라이언트 계약, 배포 설정 및 데이터베이스 스키마와 호환됩니다.

### 이전 절차

1. `Schema-Version: V14`를 적용한 `4.4.0` 설치 환경의 `/updates` 화면에서 `4.4.1`을 적용합니다. 호스트 업데이터는 릴리스 JAR를 `SHA256SUMS`로 검증하고 기존 JAR를 백업한 뒤 두 서비스를 재시작합니다.
2. 업데이터에 `SUCCEEDED`가 표시되고 두 서비스의 `/healthz`가 `UP`인지 확인합니다. 관리 콘솔에서 개편된 개요와 출시 기준을 확인합니다.
3. 상태 확인에 실패하면 업데이터가 `ROLLED_BACK`을 표시하는지 확인합니다. 기본 Linux 인스턴스에서 수동으로 되돌리려면 `sudo systemctl stop veridger veridger-admin`으로 서비스를 중지하고, 백업한 `4.4.0` JAR와 `.installed-version` 파일을 `/opt/veridger`에 복원한 뒤 `sudo systemctl start veridger veridger-admin`으로 시작합니다. 두 서비스의 `/healthz`가 `UP`인지 확인합니다.

### 추가

상단에 현재 메뉴를 표시합니다. 모바일 메뉴와 기록 표를 키보드로 탐색할 수 있습니다.

### 변경

- 개요에서 MCP 상태, 프로젝트 선택과 작업 수를 검토 대기열 위에 표시합니다.
- 기록 목록의 날짜 조건을 펼침 영역에 모았습니다. 출시 기준 필터는 접을 수 있는 마일스톤 요약 위에 배치했습니다. 출시 기준과 이력 결과가 여러 페이지면 표 위아래에 페이지 이동을 표시합니다.
- 긴 출시 기준 식별자와 본문을 요약해 표시합니다. 필요한 경우 전문과 이력 원본 JSON을 확인할 수 있습니다.
- 세션 권한 필터와 요약을 좁은 화면에 맞춰 배치하고 긴 세션 ID를 줄바꿈합니다.

### 제거

출시 기준 상세에 중복으로 표시되던 전체 이력 링크를 최근 변경 영역에 모았습니다.

### 보안

기존 관리자 인증 및 권한 요건이 적용됩니다.

### 요구 사항

- 서버와 클라이언트 훅은 `JDK 25`가 필요합니다.
- 데이터베이스는 `Schema-Version: V14`가 필요합니다.

### 알려진 제한

좁은 화면에서는 열이 많은 기록 표를 가로로 스크롤해야 할 수 있습니다.
