# veridger 4.3.2

## English

### Summary

`4.3.2` is a backward-compatible patch release on `Schema-Version: V13` that fixes a misleading `ledger_whoami` response and clarifies MCP tool descriptions for Veridger's single-connection reviewer workflow. Previously, `ledger_whoami` hardcoded the author channel and returned `can_verify_login` as `false` and `session_user` as `ledger_author` even for sessions holding an active `verify` grant, causing agents to mistakenly treat the connection as ineligible for independent reviews. `ledger_whoami` now returns `can_verify_login` as `true` and `session_user` as `ledger_reviewer` whenever the caller holds at least one live `verify` grant, and tool descriptions for `ledger_whoami`, `ledger_review`, and `ledger_review_correct` explicitly document the single-connection model.

### Breaking changes

There are no breaking MCP tool, REST API, database schema, CLI, or client hook changes in this release. `4.3.2` stays on `Schema-Version: V13`, so `4.3.1` installations can upgrade directly (including from the Admin Web `/updates` page) without running `ledger-cli migrate`.

### Migration

1. Build the `4.3.2` jars with `./gradlew assemble` or update directly from `/updates` (or download and verify `SHA256SUMS` from the `4.3.2` release).
2. If upgrading from `4.3.1` (`Schema-Version: V13`), replace the server JARs and restart both services; no database migration is required.
3. Verify `/healthz` on the MCP server and Admin Web, and refresh downstream MCP gateway/portal tool caches if an MCP proxy caches tool descriptions.
4. Roll back by restoring the `4.3.1` JARs; no database changes were made.

### New

- **Live `verify`-grant reflection in `ledger_whoami`**: `WhoamiService` now evaluates whether the authenticated caller holds any live `Scope.VERIFY` grant and sets `can_verify_login` to `true` and `session_user` to `ledger_reviewer` when active (reverting to `false` and `ledger_author` once expired or revoked).

### Changed

- **Clarified EN/KO MCP tool descriptions (`mcp.properties`, `mcp_ko.properties`)**: Updated `ledger_whoami`, `ledger_review`, and `ledger_review_correct` descriptions to state explicitly that Veridger uses a single MCP connection with no separate reviewer login, and that any independent session holding a live `verify` grant for a project invokes `ledger_review` and `ledger_review_correct` directly (subject to `SAME_SESSION`).

### Removed

No MCP tools, REST endpoints, CLI commands, database tables, or configuration properties were removed in this release.

### Security

- Preserves all `SAME_SESSION` independence checks and per-project `verify` grant authorization inside `ledger_review` and `ledger_review_correct`; `ledger_whoami` remains strictly read-only and never grants additional privileges.

### Requirements

- Java 25 runtime (`JDK 25`) on server and client hosts.
- Database on `Schema-Version: V13`.

### Known limitations

- Downstream MCP portals or clients that cache tool schemas may continue displaying earlier tool descriptions until the server entry is refreshed or reconnected.

## 한국어

### 요약

`4.3.2`는 `Schema-Version: V13`을 유지하는 하위 호환 패치 릴리스로, `ledger_whoami`의 오해를 유발하는 응답을 바로잡고 Veridger의 단일 연결 검수 워크플로를 MCP 도구 설명에 명확히 반영했습니다. 기존에는 `ledger_whoami`가 작성자 채널을 고정해 호출하여 `can_verify_login`이 `false`, `session_user`가 `ledger_author`로 반환되었으며, 활성 `verify` 권한을 보유한 세션조차 공식 검수 로그인으로 인식하지 못하는 문제가 있었습니다. 이제 `ledger_whoami`는 `can_verify_login`을 `true`, `session_user`를 `ledger_reviewer`로 반환하며(활성 `verify` 권한을 1건 이상 보유한 경우), `ledger_whoami`, `ledger_review`, `ledger_review_correct` 도구 설명에 단일 연결 모델을 명시했습니다.

### 호환되지 않는 변경

이 릴리스에는 MCP 도구, REST API, 데이터베이스 스키마, CLI 또는 클라이언트 훅의 호환성 파괴 변경이 없습니다. `4.3.2`는 `Schema-Version: V13`을 유지하므로 `4.3.1` 설치 환경은 관리 웹 `/updates` 페이지를 포함해 `ledger-cli migrate` 없이 바로 업그레이드할 수 있습니다.

### 이전 절차

1. `4.3.2` JAR를 `./gradlew assemble`로 빌드하거나 `/updates`에서 바로 업데이트합니다(또는 `SHA256SUMS`를 `4.3.2` 릴리스에서 내려받아 검증합니다).
2. `4.3.1`(`Schema-Version: V13`)에서 업그레이드하는 경우 서버 JAR를 교체하고 두 서비스를 재시작하며, 데이터베이스 마이그레이션은 필요하지 않습니다.
3. MCP 서버와 관리 웹의 `/healthz`를 확인하고, 도구 설명을 캐시하는 MCP 게이트웨이·포털을 사용하는 경우 도구 정의를 새로고침합니다.
4. 롤백 시 `4.3.1` JAR를 복원하면 되며 데이터베이스 변경은 없습니다.

### 추가

- **활성 `verify` 권한의 `ledger_whoami` 반영**: `WhoamiService`가 인증된 호출자의 활성 `Scope.VERIFY` 권한 보유 여부를 평가해 활성 상태일 때 `can_verify_login`을 `true`, `session_user`를 `ledger_reviewer`로 반환합니다(만료 또는 회수 시 `false` 및 `ledger_author`로 복귀).

### 변경

- **한·영 MCP 도구 설명 명확화 (`mcp.properties`, `mcp_ko.properties`)**: `ledger_whoami`, `ledger_review`, `ledger_review_correct` 설명에 Veridger는 별도의 검수 전용 로그인 없이 단일 MCP 연결을 사용하며, 대상 프로젝트의 활성 `verify` 권한을 가진 독립 세션이 `ledger_review`와 `ledger_review_correct`를 직접 호출한다는 점(`SAME_SESSION` 준수)을 명시했습니다.

### 제거

이 릴리스에서 제거된 MCP 도구, REST 엔드포인트, CLI 명령, 데이터베이스 테이블 또는 설정 항목은 없습니다.

### 보안

- 모든 `SAME_SESSION` 독립성 검사와 프로젝트별 `verify` 권한 인가가 `ledger_review`와 `ledger_review_correct`에서 그대로 유지되며, `ledger_whoami`는 엄격한 읽기 전용 조회로 추가 권한을 부여하지 않습니다.

### 요구 사항

- 서버 호스트 및 클라이언트 호스트의 Java 25 런타임(`JDK 25`).
- `Schema-Version: V13` 데이터베이스.

### 알려진 제한

- 도구 스키마를 캐시하는 하위 MCP 포털이나 클라이언트는 서버 항목을 새로고침하거나 재연결하기 전까지 이전 도구 설명을 계속 표시할 수 있습니다.
