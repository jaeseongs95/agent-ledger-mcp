# veridger 7.0.0

## English

### Summary

`7.0.0` keeps administrator filters after changes, displays project names consistently, and expands project-version support in MCP. The MCP request and response schemas changed, so this release increments the major version.

### Breaking changes

- `ledger_projects` now returns `display_name` alongside the existing project identifier and code. Clients that validate the old result shape must refresh their schema.
- `ledger_projects` accepts optional `project` and `display_name` filters. `ledger_search`, `ledger_specs`, `ledger_tasks`, and `ledger_criteria` accept an optional `project_version` filter. Clients that cache tool definitions should reload them after upgrading.
- `ledger_batch` operations with `op=project_version` accept optional `link_items` and `unlink_items` by record type. The existing `link_issue_ids` and `unlink_issue_ids` inputs remain supported.

### Migration

1. Download the release files and verify them against `SHA256SUMS`. Back up the current installation and database.
2. Upgrade the existing installation with `sudo sh install.sh --version=v7.0.0` on Linux or `install.cmd --download v7.0.0` on Windows. Both services continue to use `Schema-Version: V16`.
3. Confirm both services report `UP` at `/healthz` and refresh MCP tool definitions. If rollback is needed, stop both services, restore the backed-up `6.0.0` installation and configuration, and repeat the health checks.

### New

Agents can link and unlink existing issues, specifications, tasks, and release criteria on a project version in one batch and filter ledger records by project version.

### Changed

- Administrator list filters survive saves and edits. Session permission controls display the configured project names while retaining the corresponding project identifiers.
- MCP tool descriptions distinguish cross-record search, lists by record type, detail lookup, and batch changes.
- The project READMEs are shorter, with detailed instructions in the guides. Release candidates are validated separately and publish quality badges for the verified analysis.

### Removed

No MCP tools or deployment settings were removed.

### Security

Session permissions still govern batch writes. Release badge publication uses a separate read credential and verifies that the badges match the candidate's successful analysis.

### Requirements

- `JDK 25` for servers and client hooks.
- PostgreSQL with `Schema-Version: V16`.

### Known limitations

Version links apply to issues, specifications, tasks, and release criteria.

## 한국어

### 요약

`7.0.0`은 관리자 화면에서 변경 후에도 검색 조건을 유지하고, 프로젝트 이름을 일관되게 표시하며, MCP의 프로젝트 버전 관리를 확장합니다. MCP 요청 및 응답 스키마가 바뀌어 주 버전을 올렸습니다.

### 호환되지 않는 변경

- `ledger_projects`는 기존 프로젝트 식별자와 코드에 더해 `display_name`을 반환합니다. 이전 응답 구조를 검증하는 클라이언트는 스키마를 갱신해야 합니다.
- `ledger_projects`는 선택 필터 `project`와 `display_name`을 지원합니다. `ledger_search`, `ledger_specs`, `ledger_tasks`, `ledger_criteria`는 선택 필터 `project_version`을 지원합니다. 도구 정의를 캐시하는 클라이언트는 업그레이드 후 다시 불러와야 합니다.
- `ledger_batch`에서 `op=project_version` 작업은 항목 유형별로 선택 입력 `link_items`와 `unlink_items`를 받습니다. 기존 `link_issue_ids`와 `unlink_issue_ids`도 계속 지원합니다.

### 이전 절차

1. 릴리스 파일을 내려받아 `SHA256SUMS`로 검증합니다. 기존 설치 환경과 데이터베이스를 백업합니다.
2. 기존 설치를 업그레이드합니다. Linux는 `sudo sh install.sh --version=v7.0.0`을 실행하고 Windows는 `install.cmd --download v7.0.0`을 실행합니다. 두 서비스는 계속 `Schema-Version: V16`을 사용합니다.
3. 두 서비스가 `/healthz`에서 `UP`을 반환하는지 확인하고 MCP 도구 정의를 갱신합니다. 되돌려야 하면 두 서비스를 중지하고 백업한 `6.0.0` 설치 환경과 설정을 복원한 뒤 상태를 다시 확인합니다.

### 추가

에이전트는 기존 이슈·명세·작업·출시 기준을 하나의 일괄 요청으로 프로젝트 버전에 연결하거나 연결을 해제할 수 있으며, 장부 항목을 프로젝트 버전으로 필터링할 수 있습니다.

### 변경

- 관리자 목록은 저장과 수정 뒤에도 검색 조건을 유지합니다. 세션 권한 화면은 프로젝트 식별자를 유지하면서 설정된 프로젝트 이름을 표시합니다.
- MCP 도구 설명에서 통합 검색, 유형별 목록, 상세 조회, 일괄 변경의 역할을 구분합니다.
- 프로젝트 README를 줄이고 상세 안내를 가이드에 담았습니다. 릴리스 후보는 별도로 검증하며, 검증한 분석 결과의 품질 배지를 발행합니다.

### 제거

제거된 MCP 도구나 배포 설정은 없습니다.

### 보안

일괄 기록에는 세션 권한을 적용합니다. 릴리스 배지 발행은 별도의 읽기 자격 증명을 사용하고 배지가 후보의 성공한 분석 결과와 일치하는지 확인합니다.

### 요구 사항

- 서버와 클라이언트 훅 실행에 `JDK 25`가 필요합니다.
- PostgreSQL에 `Schema-Version: V16`이 필요합니다.

### 알려진 제한

버전 연결은 이슈·명세·작업·출시 기준에 적용됩니다.
